\#注释行，导入时被忽略
!标题行，即标识表头，不带!的表示表体，即要导入的具体数据行

<p><span style='color:#0000CC'>I:object_desc.MAND</span></p>

<p><em><strong>NOTE 2</strong></em>: To set mandatory master form attributes when the item is created the field name must start with the master form type and not the shortcuts IM or RM since these are not treated as general properties. So, for example use:-</p>
<p><span style='color:#0000CC'>TW4_ItemMaster:project_id.MAND</span></p>
<p>And not</p>
<p><span style='color:red'>IM:project_id.MAND </span></p>

<td><p><strong>.FIND=</strong>&lt;<em>search_attrs&gt;</em></p>
<p><span style='color:red'><em>查找其他有关系的对象</em></span></p></td>
<td><p><strong>[10.11.0]</strong> Finds other objects to set on referenced attributes. For example can be used to find a <strong>TC_Project</strong> object to set as the <strong>owning_project</strong>.</p>
<p>The <em>&lt;search_attrs&gt;</em> specifies the class of object to find and the attributes to search on in the format:-</p>
<p><span style='color:#0000CC'>&lt;<em>Class</em>&gt;&lt;<em>sep</em>&gt;&lt;<em>attr1</em>&gt;[&lt;<em>sep</em>&gt;&lt;<em>attr2</em>&gt;[…]]</span></p>
<p>I.e. a class and at least one attribute separated by a configurable separator using the config option <strong>FIND FIELD DATA SEPARATOR</strong>, or a comma by default.</p>
<p>Values supplied in the data line, using the same separator, will supply values for each attribute to search on. Any value can be blank to not search on a specific attribute for that data line. A blank value will perform no search at all.</p>
<p>If more than one value is found for a non-array attribute then the first object will be set for the attribute. An array attribute will have all objects set.</p>
<p>For example, to set <strong>owning_project</strong>:-</p>
<p><span style='color:red'>I:owning_project.FIND=TC_Project,project_id</span></p>
<p><span style='color:#0000CC'>Project X</span></p>
<p><span style='color:#0000CC'>Project Y </span></p>
<p>The first line here is the header field and the others are example data values.</p>
<p>An asterix, *, can be used in a value to perform a wild card search.</p>
<p>For example, to find a list of test projects to set as a project list where the <span style='font-weight:bold'>project ID</span> starts with <span style='color:#0000CC'>Test</span> and the <span style='font-weight:bold'>name</span> = <span style='color:#0000CC'>Test</span>:-</p>
<p><span style='color:#0000CC'>I:project_list.POM.FIND=TC_project,project_id,project_name</span></p>
<p><span style='color:#0000CC'>Test *,Test</span></p>
<p>Note that this example also uses the <span style='color:#0000CC'>.POM</span> field modifier as <span style='color:#0000CC'>project_list</span> is normally a non-modifiable attribute.</p>
<p><em><strong>NOTE 1</strong></em>: Currently only <strong>string</strong> attributes can be searched on to find objects using the <strong>.FIND</strong> modifier.</p>
<p><em><strong>NOTE 2</strong></em>: <strong>[12.6.0]</strong> If the class of object being searched for is descended from Item or ItemRevision then the key fields <strong>ItemID</strong> and <strong>RevID</strong> can be used to find an item or rev.</p></td>
</tr>
<tr>
<td><strong>.KEY</strong></td>
<td><p><strong>[11.0.0]</strong> Indicates MultiField Key fields to provide unique property values to find specific items that can have the same Item ID.</p>
<p>To provide different keys for parent and child items, e.g. in bom mode child keys must be further identified by adding the .CHILD modifier.</p></td>
</tr>

<p>This is used in conjunction with the <strong>.KEY</strong> modifier to differentiate between parent and child MultiField Key fields.</p></td>
</tr>
<tr>
<td><strong>.BOM_OCC_KEY</strong></td>
<td><strong>[11.0.0]</strong> Identifies fields during a BOM update that are used to identify an occurrence to be updated. This fields can be used as well as or instead of the fields specified with the BOM UPDATE ID FIELDS configuration option</td>
</tr>
<tr>
<td><strong>.PROPAGATE</strong></td>
<td><p><strong>[12.0.0]</strong> Identifies fields to be set on propagated objects when using PROPAGATION PATHs. These fields should also be set as colon fields with the object type of <strong>*</strong>, e.g.:-</p>
<p><span style='color:blue'>*:owning_user.PROPAGATE</span></p>
<p>See the section <span style='text-decoration: underline;color:blue'>2.8</span> for full details on propagating values to objects under the current object being updated, e.g. item or rev.</p></td>
</tr>

文件最前面可以加配置，优先级高于cfg（不同模式导入的配置文件）文件的配置。

例如：
ITEM TYPE = Document
!~ItemID~RevID~Desc~Name~Owner~Group
GUY12345~A~The Item Description~ITEM-NAME~infodba~dba
如果需要在列中忽略某一列，用**Ignore**:
<span style='color:blue'>如：</span>
<span style='color:blue'>**Ignore**:Owner~**Ignore**:Group</span>
<span style='color:blue'></span>
如果设置某列为空或null，则将值设置为NULL.

END-OF-FILE为结束行标识。

**owning_user必须写全值，如林东乐(ldl)，TC12版本后只需要写id即可。**

**支持创建关系时，创建关系属性功能：**
IMAN_specification:*\<property\>*

*支持指派对象到某项目：*
<span style='color:blue'>(Dataset):project_ids</span>
Or
DSET:project_ids.，多个项目用,隔开。设置为NULL，为移出所有分配的项目。

支持更新对象的UID：（11.3开始）
ItemID.TAG
