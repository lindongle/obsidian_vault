<span style='background: white'>什么是RACI模型？ 释义</span>
<span style='background: white'>RACI是一个相对直观的模型，用以明确组织变革过程中的各个角色及其相关责任。 我们知道，变革过程是不可能自发或者自动进行的， 必须有人对其进行作用，促使进程发生变化。 因而，就很有必要对谁做什么，以及促发什么样的变革进行定义和描述。</span>
<span style='background: white'>除了RACI以外，还有RASCI或RASIC都是用来描述变革过程中的角色、任务的。</span>
<span style='background: white'>RACI的具体含义 英文缩写</span>
<span style='color:#4F4F4F'>· 谁负责（R = Responsible）， 即负责执行任务的角色，他/她具体负责操控项目、解决问题。</span>
<span style='color:#4F4F4F'>· 谁批准（A = Accountable）， 即对任务负全责的角色，只有经他/她同意或签署之后，项目才能得以进行。</span>
<span style='color:#4F4F4F'>· 谁支持（S = Supportive）， 即提供信息资源，辅助执行任务的人员。</span>
<span style='color:#4F4F4F'>· 咨询谁（C = Consulted）， 拥有完成项目所需的信息或能力的人员。</span>
<span style='color:#4F4F4F'>· 通知谁**(I =Informed), 即拥有特权、应及时被通知结果的人员，却不必向他/她咨询、征求意见。**</span>
<span style='background: white'>RACI模型通常利用RACI表来帮助讨论、交流各个角色及相关责任。（参见右图）</span>
<span style='background: white'>RACI的步骤</span>
<span style='background: white'>1. 辨识整个流程、找出各项活动，将它们记录在RACI表的左侧。</span>
<span style='background: white'>2. 辨识流程、活动中的所有角色，将它们记录在RACI表的上方。</span>
<span style='background: white'>3. 完成RACI表的方格单元： 辨识每一个流程、活动的角色（R、A、S、C、I）。</span>
<span style='background: white'>4. 每一个流程最好只有一个“R”角色，这是RACI的一般原则。 当一个流程找不到“R”角色时，则出现缺口。 当一个流程有多个“R”角色时，则出现交叠。</span>
<span style='background: white'>5. 解决交叠问题。 每个流程只能有一个“R”角色，以便明确流程的具体拥有者和责任。 如果不止一个“R”存在，那么就要对该流程进行再分解，然而再对“R”进行分配。</span>
<span style='background: white'>6. 解决缺口问题。 如果某个流程找不到“R”角色，这时对流程或项目负全责的权威人士则应该在现有角色中（或者发现新人选）挑选、任命一人担任“R”。 更新RASCI表，对各个角色及其相关责任进行阐述</span>
