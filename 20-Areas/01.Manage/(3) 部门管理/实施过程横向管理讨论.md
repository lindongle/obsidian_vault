1.  人员培养策略调整
    1.  **新员工**由Teamleader所在项目直接带策略；--部门先开展
    2.  滚动跨级能力工作模式，即初级顾问干部分中级顾问工作，中级顾问干部分项目经理工作，项目经理干实施顾问工作，并分精力培养新人。
2.  组织及业务调整
    1.  交付部门整合，或大项目组制，取消部门界限；-搁置
    2.  提升原部门副手（海豹/李祥）的权利及责任要求，原teamleader不再直管交付，作为横向部门监控项目执行，控制项目范围及延期。--任命
    3.  强化当前售前方案部（形同虚设）职能，售前兼任业务顾问模式，或将业务顾问与售前合并部门。新项目任命，前期售前工程师作为项目的SA参与到项目。
    4.  售前方案与实施方案PPT及word素材的整合及包装，售前所需标书/解决方案/讲标PPT的清单整理或模块标识。
3.  **核心业务解决方案模块化**：--标注优先级
    1.  知识库/分类库管理及推送方案
        1.  物料库/名称库结构
        2.  项目库与时间表的关联结构关系
        3.  知识推送方式
        4.  物料入库方式，先创建入库？license太少，发布后自动入库？如何更新参数？标准化来填写参数？流程中开权限？
    2.  BOM管理：
        1.  BOM：D/E/P/M的定义模糊；
        2.  确定D/E一套或多套BOM，E/P一套或多套BOM的选择时机；
        3.  两套BOM的管理方案，Design-Part?多结构管理器？多结构时子件换号的逐层换号问题；
        4.  多工厂BOM的管理方案，多Item类型/多视图/结构管理器？工厂信息存储位置，视图？表单？新item的版本？下发时选择或handler中默认？
        5.  提前采购BOM的管理及与物料需求重复的解决方案。
    3.  变更管理：
        1.  PR-ECR-ECN之间的工作内容的串并性；
            1.  PR不需要变更license，与第三方集成？还是不引导
            2.  ECR变更申请，是否需要修订变更数据，修订E还是P?
            3.  ECN执行，新版本数据发布后开始ECN还是作为ECN实施计划的一部分？
            4.  执行闭环，流程控制？第三方集成？
            5.  临时变更的处理方案，多台产品物料不同，单个产品部分物料采购不到
    4.  项目管理：
        1.  交付管理中心克隆
        2.  交付物的流程与任务流程的关联？
        3.  计划的分解权限问题
    5.  驾驶舱：
        1.  通用驾驶舱
            1.  整体用户/在线用户/离职（非活动）用户统计；
            2.  物料的新增/发布统计；
            3.  变更统计维度；
            4.  审批流程统计维度；
            5.  项目状态/任务状态/交付物完整性维度；
    6.  独立license模块的开发替代性方案：
        1.  分类/变更/MCAD集成/多结构管理器
4.  实施过程优化
    1.  确定版本选择的原则；
    2.  标准虚拟机环境的搭建与维护；
    3.  标准业务模型及常用首选项的梳理；
        1.  Item/Part/Design
        2.  去变更模块的变更管理模型；
        3.  封装集成配置-dwg/step等；
        4.  标准类型/属性/lov的确定；
        5.  通用首选项的整理及导出xml；
        6.  通用流程模板及handler的整理及导出xml；
        7.  针对不同类型，通用查询配置的导出txt；
    4.  标准SOW/蓝图方案/系统设计报告/开发规格/操作手册的整合
    5.  定期各项目系统配置及二次开发功能的收集/整合/分析梳理，驱动冉修标准插件及配置的更新
