1.  分类：
    1.  标准版
    2.  敏捷版
    3.  人天版
2.  区分原则：
    1.  包结果：区分标准版/敏捷版
        1.  人天总数/合同额；
        2.  周期；
        3.  是否成熟行业/成熟业务；
        4.  战略合作；--标准版
3.  目标：
    1.  标准版：业务流程为主，保证应用效果；
    2.  敏捷版：功能培训为主，最佳实践导入，侧重于交付；
4.  实施阶段、活动、输入输出（固化矩阵及模板）
    1.  阶段：
        1.  标准版：
            1.  项目准备（立项）阶段；
            2.  项目启动阶段，项目策划，阶段划分；
            3.  需求分析及方案设计阶段（迭代方案-设计-测试-上线）；
                1.  图文档管理（知识库/文档/流程/电子签字/文档编码/文档变更）
                2.  物料及BOM管理、变更（PDM-CAD集成/分类库）
                3.  PBOM及ERP集成
                4.  BOP及ERP集成
                5.  项目管理、仿真数据、需求管理
            4.  系统设计及开发阶段；
            5.  用户测试阶段；
            6.  上线准备及切换阶段；
            7.  上线支持及验收阶段；
            8.  运维阶段；
        2.  敏捷版：
            1.  项目准备（立项）阶段；
            2.  项目调研及部署阶段；（调研后直接出整体方案进行评审，预配置）
            3.  系统培训及上线切换；
            4.  系统优化、验收及运维；
        3.  人天版：
            1.  项目准备（立项）阶段；
            2.  技术支持阶段；
                1.  流程制度；--人天确认单/确认流程/回款流程
    2.  标准化工作流程及关键注意事项
        1.  模板标准化；--拉清单/确定必须执行的几个；
        2.  数据标准化，包括安装路径、模型命名等；--初始化BMIDE模板/首选项初始化导入包；
        3.  工作方法标准化；
5.  评审矩阵
    1.  关键里程碑节点计划评审；
        1.  方案节点；
        2.  上线节点；
        3.  验收节点；
    2.  关键交付物质量评审；
        1.  项目进度计划；
        2.  总体设计方案；
        3.  系统设计报告（含RTM及二次开发规格）；
        4.  UAT场景；
        5.  上线倒排计划；
    3.  关键阶段汇报PPT评审；
        1.  启动会PPT；
        2.  方案汇报会PPT；
        3.  上线动员会PPT；
        4.  验收总结会PPT；
    4.  评审内容及责任人；
        1.  编制Cheklist；
        2.  交付物线上审批；
        3.  PPT试讲流程；
6.  项目横向管理
    1.  质量审计；
        1.  每个项目做1-2次，定义责任人；
        2.  按里程碑过程（尽量里程碑到达前2周）；
        3.  定义审计内容的Checklist；
        4.  资源计划投入偏差；--实际人天的统计（每周）--工具统计
        5.  重点抽查会议纪要及签到/签字；
        6.  现场巡查机制；
    2.  风险及问题跟踪；
        1.  建立单独的风险及问题处理库，保留每次的记录；
        2.  每两周例会增加对风险及问题解决措施及状态的跟踪及更新；
    3.  过程方案内部讨论机制；
        1.  建立公司级业务顾问团队（虚拟组织-售前）；
        2.  业务顾问方案阶段每1-2周组织一次方案的头脑风暴，协调顾问团队参与；
        3.  提前准备讨论的内容/方案的选项/项目组内部倾向的方案及理由/客户相关资料/系统按需准备Demo；
    4.  需求管理控制；
        1.  建立需求管理控制流程；
            1.  SOW与方案的差异备忘；
            2.  每两周梳理项目过程中的需求或不确定是否需求内容，工作量在1人天以上；
            3.  提前与客户确认我方内部控制流程；
        2.  讨论需求控制内容；
            1.  定义SOW范围内外需求的区分原则；
            2.  模糊内容，定义我们内部认可的区分原则，如根据现场的沟通、耗费人天、商务价值等；
    5.  项目总结及分享；
        1.  典型项目分享机制及流程；
        2.  优秀方案的判断标准及奖励措施；
        3.  项目虚拟机及真实数据截图/录屏；
        4.  经验教训总结；
        5.  新机会总结；
        6.  工作量标准化库的建立和更新；
7.  计划
8.  资源分工（正激励-立项）
9.  持续过程，定义迭代
