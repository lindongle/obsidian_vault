1.  测试环境：
    1.  搭建OOTB环境，使用Oracle数据库（==字符集？==），确保功能模块与原系统完全一致；
        1.  目前sqlserver字符集是Latin1_General_CI_AS，TC的字符集是ISO-8859-1，测试环境的字符集是Chinese_PRC_CI_AS；
    2.  部署BMIDE；
    3.  验证登录及卷/临时卷/登录测试
    4.  使用sql dev工具进行表导出导入（每个表单独导入，根据两个字段类型做好映射），表特别多，花很长时间，做好类型映射记录，为后续生产环境整体表类型映射做基础，如果个别类型映射出现一对多的情况，整体导入后单独处理；
    5.  备份tcdata的tc_profile文件，覆盖tcdata，根据Oracle重新配置tc_profile文件；
    6.  执行登录验证，处理登录问题；
2.  测试环境重新模拟以下生产环境（3）的步骤，即提前重复3的步骤；
3.  将测试环境升级到11.2，再升级到13.3，再升级到TC14.-详见后续升级工作清单。
4.  进行升级后处理及验证；
5.  组织用户测试问题处理；
6.  最终生产环境：
    1.  备份并还原到测试环境，整体迁移到原测试环境中；
    2.  部署BMIDE；
    3.  验证登录及卷/临时卷/登录测试
    4.  使用sql dev工具进行导出导入所有表，映射根据测试时的映射关系建立好；
    5.  执行导入，并根据测试时特殊字段类型进行手动转换（sql dev工具单独表进行导出导入）
    6.  进行登录验证；
    7.  将环境升级到11.2，再升级到13.3，再升级到TC14.
    8.  进行升级后处理及验证；
7.  升级及转换同步思路：转换和升级同步弄，升级有标准的工具及教程，不区分数据库，得在准备一套测试环境做升级验证，把升级整体详细步骤验证完形成文档。同时在刚搭的环境里做转换验证，验证完后，利用升级的文档在转换后的环境里执行一遍。
