# 一、原CPC流程归属问题
## <span style='color:#2E75B5'>归属选择</span>
<span style='color:black'>OA和PLM</span>
## <span style='color:#2E75B5'>说明</span>
<span style='color:black'>OA和PLM中流程模板的修改及权限后面均由IT统一管理，OA上可以根据需要建立新的流程。</span>
## <span style='color:#2E75B5'>归属原则</span>
<span style='color:black'>1、PLM只管理研发相关流程；</span>
<span style='color:black'>2、如需总裁、副总裁高级领导审批时，建议在OA上审批，便于出差审批或安装。</span>
<span style='color:black'>3、如研发部部门只是审核，不负责文件或表单的管理，建议放在OA上审批。</span>
<span style='color:black'>4、非研发过程的工作，如请假、日常行政管理申请等，不要放到PLM，归属到OA。</span>
<span style='color:black'>5、非研发部门（含工艺）负责编制或发起的流程，放OA中。</span>
<span style='color:black'>6、由研发部门发起，但审核部门均由其他研发以外的审批，建议放到OA中，避免因只使用审批功能造成PLM的许可点数浪费，审批后的文件可扫描上传到PLM系统进行归档，走一键发布。如项目立项报告等</span>
# 二、PLM流程模板统一
## <span style='color:#2E75B5'>标准审批节点</span>
<span style='color:black'>流程发起-**编制、校对、审核、标准化、会签（多部门，工艺、生产、采购、财务等按需设置并行审批）、批准**-流程归档</span>
## <span style='color:#2E75B5'>原则</span>
<span style='color:black'>1、相同审批步骤节点（相同或不同角色）统一成一类模板，发起人对于角色按需自行选择。</span>
<span style='color:black'>2、审批步骤中相似节点合并或统一命名</span>
<span style='color:black'>3、审批步骤只关联角色或组（即岗位或部门），不关联具体人员，避免人员变动造成管理制度及系统配置的调整。</span>
## <span style='color:#2E75B5'>建议方案</span>
### <span style='color:#5B9BD5'>前提：发布研发过程评审级别表（管理制度或控制程序）</span>
<span style='color:black'>1）定义流程模板对应的研发文件的清单；</span>
<span style='color:black'>2）定义流程模板中每步流程的审批参与级别及范围；</span>
### <span style='color:red'>建议方案一</span>
<span style='color:black'>**按文件类型分：**</span>
<span style='color:black'>例如：</span>
<span style='color:black'>技术文件发布流程：编制、校对、审核、标准化、会签（生产/工艺）、批准</span>
<span style='color:black'>设计更改流程：编制、校对、审核</span>
<span style='color:black'>工程更改：：编制、校对、审核、标准化、会签（多部门）、批准</span>
<span style='color:black'>自制件编码申请流程：编制、审核、维护</span>
<span style='color:black'>。。。</span>
### <span style='color:#5B9BD5'>建议方案二</span>
<span style='color:black'>**按审批步骤分：**</span>
<span style='color:black'>例如：</span>
<span style='color:black'>一步流程：编制-发布</span>
<span style='color:black'>二步流程：编制、审核、发布</span>
<span style='color:black'>三步流程：编制、校对、审核、发布</span>
<span style='color:black'>四步流程：编制、校对、审核、标准化、发布</span>
<span style='color:black'>五步流程：编制、校对、审核、标准化、会签、发布</span>
<span style='color:black'>六步流程：编制、校对、审核、标准化、会签、批准</span>
# <span style='color:#1E4E79'>三、电子签字（待定）</span>
<span style='color:black'>**说明：PLM系统中已经存在发布流程，且每个流程都有审批记录。**</span>
## <span style='color:#2E75B5'>建议方案一：</span>
<span style='color:black'>不出纸质版本的文件，不需要电子签字，系统发布流程控制冻结状态（插小旗），实时查看审批记录。</span>
<span style='color:black'>需要提供纸质的文件，按照确定的流程模板，统一文档的审批模板。</span>
## <span style='color:#2E75B5'>建议方案二：</span>
<span style='color:black'>均不进行电子签字，将文件中签字区域，换成二维码方式（PDF版），扫描二维码查看流程审批记录或该文件的其他信息。如下某文件二维码信息（可自定义）。</span>

# <span style='color:#1E4E79'>四、项目管理报工流程及交付物审批流程</span>
## <span style='color:#2E75B5'>任务的提交建议过程（相对独立及关联）</span>
<span style='color:black'>1、任务不含交付物的，完成后，发起完工流程-项目经理审批-自动更新进度。</span>
<span style='color:black'>2、任务含交付物的，编制交付物-发起交付物的对应审批流程（按评审级别表），审批发布。所有交付物发布完成后，对该任务发起任务完工流程-项目经理审批（检查所有交付物是否已经发布）-自动更新进度。</span>
