1、备份数据
tcdata、数据库导出dmp、volume
2、还原数据库
导出数据库：
expdp system/infodba@tc DIRECTORY=backdir DUMPFILE='XXX.dmp' schemas=infodba LOGFILE='expdp.log'
1）新数据库服务器，新建文件夹D:\TC\DBBackup，将备份的dmp文件夹解压到此文件夹中。
2）创建数据库目录并授权。
sqlplus system/infodba@tc回车
create directory backdir as 'D:\TC\DBBackup';回车
grant read,write on directory backdir to infodba;回车
exit退出
3）清空现有数据库，并创建空数据库。
sqlplus system/infodba@tc;回车，如果已在sql连接环境，此处略。
@D:\oracle\infodba\product\12.2.0\dbhome_1\assistants\dbca\templates\tc_unpopulate_db.sql回车，再回车
exist退出
4）查询原数据库编码格式：
sqlplus system/infodba@tc
select userenv ('language') from dual;
**SIMPLIFIED CHINESE_CHINA.ZHS16GBK**
5）恢复数据库
进入cmd
set ORACLE_SID=TC回车
set NLS_LANG=SIMPLIFIED CHINESE_CHINA.ZHS16GBK回车
impdp system/infodba@tc directory=backdir dumpfile='XXXX.dmp' schemas=infodba exclude=USER logfile=impdp.log回车。

4、卷恢复
1）将新卷重命名，将旧volume文件夹放到相同目录。并修改此文件夹的完全控制权限给当前用户。
2）导出卷信息。
TC命令窗口中执行backup_xmlinfo -u=infodba -p=pdm_1234 -g=dba，在tc_root\tc_menu下找到backup.xml文件。
3）修改主FSC服务的FSCMASTER配置信息。
用backup.xml
“fmsenterprise”的值替换fsc主文件“fmsenterprise”和“enterprise”的值
![image9](4630ca6dba87494881d3d22b91fe2182.png)
用backup.xml“volumeUid”的值替换fsc主文件“volume id” 的值
![image10](37089da4e0a4487689d6bb3311dd2e87.png)
用backup.xml“transVolId”的值替换fsc主文件“transientvolume id” 的值
![image11](dc50117bfe934eb393119a14c3114122.png)
<span style='color:red'>4）节点1的修改后的fscmaster覆盖到节点2，并复制到POOL池的FSC中（重命名为pool池的FSC服务名称）。并重启节点1/2/pool池FSC服务。</span>
5）修改数据库卷路径及ID。
update pimanvolume set pnode_name='新卷服务器名（203虚拟ip）',pwnt_path_name='新路径l' where pnode_name ='旧卷服务名' and pvolume_name='旧卷名';
或安装plsql直接更新这个表。

5、恢复首选项
1）导出站点首选项
tc中输入命令preferences_manager -u=infodba -p=pdm_1234 -g=dba -mode=export -out_file=D:\tc_site_preferences.xml -scope=SITE
2）修改导出的首选项（或直接登录2层客户端直接修改）
Default_Transient_Server，值为pool池FSC地址http://172.16.254.200:4544
Fms_BootStrap_Urls，值为主FSC服务器的地址http://172.16.254.204:4544
Transient_Volume_Installation_Location，值修改为pool池服务器的地址或主机名172.16.254.200

![image14](1c28465ab1e648ce82c009ff9303d374.png)

4）部署BMIDE
将项目文件夹放到BMIDE文件目录下，打开BMIDE，导入项目。进行部署。

1.  恢复后检查
2.  **系统检查**
    1.  **检查服务**
检查Oracle和Teamcenter FSC服务是否已经启动
1.  **检查索引**
在Teamcenter命令窗口，输入以下命令
**index_verifier -u=infodba -p=password -g=dba \> index.sql**
在TC_ROOT下的tc_menu下会生成index.sql文件
![image16](d5752a494a6343bd99f65cbcf55ecafc.png)
打开index.sql，如果都为Rem，说明数据库索引都已建好
![image17](523b0176d0d34baf847a1cac4d681337.jpg)
如果没有创建好的数据库索引，修改index.sql文件，把里面的“Rem ”开头的行去掉，而后复制到C盘的根目录，并在DOS窗口中执行以下命令
1.  sqlplus [infodba/\<password\>@](mailto:infodba/infodba@tc9)\<oracle SID\> （连接数据库）
2.  @c:\index.sql （重置数据库索引）
3.  commit; （提交结果）
4.  exit （退出数据库）
    1.  **检查有无损坏的工作流**
在Teamcenter命令窗口，输入以下命令
**verify_tasks -u=infodba -p=pdm_1234 -g=dba**
![image18](53edf0fb49a94545a847b23e84312c37.jpg)
如果有损坏的工作流，则使用verify_tasks –m=delete –u=infodba –p=\<password\> -g=dba
1.  **检查是否可以创建数据**
从已有数据集的命名引用中导出文件 (通过)
新建ITEM (通过)
新建一个数据集 (通过)
保存数据集 (通过)
打开新建的数据集 (通过)
