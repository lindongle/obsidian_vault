设计部门
2022年8月30日
8:06
1.  部门组织情况：
    1.  研究院与项目管理部的干系：
        1.  开项目启动会，明确时间点，排项目计划；
    2.  科技质量部：主要管科研类项目、知识产权、标准化、科研经费；
        1.  标准化：国家/行业标准的申请，管理性质的标准，提供模板，进行审核并发布，标准的具体内容由研究所完成；图纸标准化审核的由研究所内部工程师兼职管理，组成标准化专委会虚拟组（各个研究所），所内没有专职标准化人员；
    3.  产业发展部：产业孵化，产品规划；
    4.  风电所：
        1.  总体设计室：4个组；
            1.  平台规划/产品规划/总体技术的规划，
                1.  主要是平台规划/技术规划，机型与模块化梳理；
                    1.  历史30-40个机型、10几个平台；
                    2.  模块化库正在梳理，还未启用；
                    3.  科研类项目机型的总体布置，由项目经理进行，由总体设计室或机械室分配项目经理，负责节点的跟踪；
                2.  标准件库管理（主要10.9级，也有8.8级）；
                3.  通用件库：准备建立，还未建立，希望单独编号，目前靠经验进行识别；
            2.  分析计算组，仿真管理，有限元分析计算；
            3.  可靠性设计组，DFMEA等；
            4.  风资源评估；现场评估，地形/运输条件，编写报告类文件
2.  项目分类：
    1.  市场项目，项目管理部担任项目经理；
    2.  科研项目，科技质量部管理，由总体设计室单独室；
3.  BOM管理：800多个（不包含外协件的下级），500多M；
    1.  整机BOM从SW导出到Excel，各个模块合起来，都是机械部分。不合并电气、叶片相关系统；
    2.  电气BOM后期需要搭入整机BOM；
    3.  机型核心大部件：
        1.  轮毂总成（加叶片为风轮总成）
            1.  变桨系统总成；
                1.  轮毂
                    1.  。。
            2.  导流罩；
            3.  导流罩支架总成；
        2.  机舱总成
            1.  轴承座装配；
            2.  内部框架总成；
            3.  主机架装配
            4.  发动机底架总成；
            5.  主机架平台总成
        3.  塔筒总成；
            1.  在BOM表中一个整体；
            2.  不出具体明细；
            3.  MDM只申请总MDM号，及必要的需要供货物料，升降电梯、高强紧固件等；
        4.  基础（地基）；
            1.  只出锚栓图；
            2.  提供项目基础载荷报告（基础数据）、安全系数、频率要求，标准基础图、锚栓结构图（未确定长度）给到设计院，设计院做初版图纸给到研究所，进行校核，仿真时和钢结构室。
        5.  叶片（去年年底，开始自主设计）；
    4.  编码：
        1.  图号19位，MDM编码
        2.  自主设计的，每个件都有图号；
        3.  对于外购件，按最小外购单元申请MDM码；
        4.  MDM物料编号申请：
            1.  各个系统单独，Excel中输入图号/材料名称/分组等信息；
            2.  导入MDM系统中，走流程进行申请；
            3.  在图号下发BOM时，完成MDM编码申请；
    5.  通用件/优选件：
        1.  目前换了新的号/MDM码也重新申请，对历史追溯和一物多码会有影响；
        2.  建议图号规则不变，也不用MD0000，使用原图号，走通用件流程，审批后进行分类到通用件库会自动打标识；
    6.  轮毂总成从自己厂区拉到风场。塔筒、叶片从供应商直接发风场；
4.  电气设计：10人
    1.  Eplan2.7；
    2.  Eplan库已经建立，但分散在不同工程师电脑中，期望后期库共享；
    3.  主控：4人，变桨2人，塔筒电气1人，使用Eplan画原理图；
    4.  发电机、变流器的规范和要求、方案，3人；
    5.  电气类系统作为一个大部件，电气设计原理图，外协给供应商，供应商会提供BOM清单及三维框架图；主控系统（供应商提供外壳体，电气室做原理图，由零部件清单）、变桨系统（电气出原理图，机械会出下级模型图）、发电机、变流器等电气件（硬件）全是外协；
    6.  目前机械与电气系统的接口目前已标准化，位置均已确定。如果是全新开发的机型，根据电气系统的尺寸给出位置，机械找位置来放；
5.  钢结构：7人
    1.  研发平台，塔筒概念设计；
    2.  所有塔筒设计随着项目走，不同项目的塔筒都不一样，定制化设计；
    3.  与机械与电气室的接口的对接，接口不标准，与载荷和仿真计算进行计算；
    4.  只做设计，不生产（风电托管生产，制造中心，内部流程，钢构制造也自行接 单），招标或图纸给业主自行招标；
    5.  基础设计，对接设计院和业主；
    6.  混凝土塔架不设计，出技术要求，只设计钢制塔筒；
    7.  痛点：
        1.  仿真报告输入的最终版需室主任签字确认；
6.  检测验证室：7人
    1.  现场的测试（机组的形势测试、电能质量测试）、震动、噪声测试；
    2.  测试设备：厂家租赁的设备；
    3.  新机组的并网要求、机型的形式实验（证书要求）、现场的问题（突发）、研究类作为需求，按计划执行测试；部分会有工作联系单进行协调；
    4.  输出测试报告、认证的证书；
    5.  结果反馈-\>测试方案/大纲-\>现场测试-\>报告及问题-\>反馈需求部门；
    6.  对外输出的报告有编校审；
    7.  目前刚开始进行一些软件测试；
        1.  主控和场控软件测试系统；
        2.  软件版本发版-\>测试用例编写（开源工具，禅道）-\>反馈开发处理-\>直至BUG满足比例要求；
        3.  禅道部署在自己电脑上；
        4.  测试用例自己写，预期后续开发参与评审；
        5.  在自己虚拟机上进行测试，也需要开发人员自己的资源；
        6.  用Excel反馈问题，跟踪问题处理进度；
        7.  应用软件都测试，烧录使用仿真工具测试；
        8.  期望软件版本与对应测试文件（测试用例/报告）的关联；
7.  软件控制室：13人
    1.  3部分业务，主控PLC，风电场的能量管理系统，文件管理系统，增加了数据采集（Sugard）监控中心的业务；
    2.  主控PLC，根据参数选择其物料硬件需要版本，做标准化，适配各种配置的接口，其他室通过纸质的软件设计输入参数表，把硬件的接口给到软件，软件汇总后进行会签，目前软件跟物料没太大关系，不同的软件包对应不同的项目；
    3.  SVN工具管理代码，修改后走解决方案下发，新版本程序及升级文档下发到生产；
    4.  通用版本发到现场，根据要求做定制化升级，通过SVN设置不同分支管理不同项目的需求；
    5.  文件管理系统，未来更换到PLM系统，目前版本管理和查询比较弱；
    6.  风电场的能量管理系统，通讯协议都是通用的；
    7.  问题：
        1.  现场问题的记录到新解决方案的下发的闭环流程；
        2.  项目上的各个版本程序的记录（包括源代码版本与程序的对应），目前通过SVN关联；
        3.  项目上软件问题的统计（问题数量、解决周期等）；
        4.  运维人员编写，问题的文件传递单，问题描述有的不清晰，需再次现场沟通；
    8.  开发工具：QT；
    9.  没有使用平台，直接原生开发；
    10. 软件测试：测试平台正在招标；软件内部交叉测试，发布的时候目前没有测试报告，目前不走代码走查；
    11. 期望：问题-\>解决方案-\>程序包关联及查询统计；
8.  机械室：20人，两个组，支撑和传动；
    1.  二级总成，由不同工程师负责，研发项目经理负责进行一级总成的装配；
    2.  大概流程：
        1.  年初科研立项（目前自己自己立项，报科技质量部审批）:任务书和计划书，出详细的项目计划（任务分到不同的部件的负责人）；总体规划部提前给图号；
        2.  概念设计，输出方案说明书（借用/重新设计）；支撑和传动合并一起写，初步整机数模的总布置评审；
        3.  详细设计，SW中做了标准件库，其他借用件从自己电脑上借用，通过单独索要或共享服务器上进行下载，不一定是最新版本，需要找原设计人员确认；
            1.  SW，填写图号/名称/所属装配图/版本号，自制件，材料通过SW的材料库选择，材料库不全的，自己创建库，查询密度。单重和总重自动计算。外购件的材料直接写成品，重量根据供应商提供的进行填写；标准件，材料中填写规格；外购件变更，图号不变，MDM码重新申请；
            2.  标准件的图号，不唯一，使用国标号作为图号，代表一系列，不同强度等级的使用相同国标号（图号），不同物料号；本地数模名称上体现规格型号来区分；
            3.  二维图，等详细设计完成后进行评审，评审完成后出图；
            4.  设计评审：科技质量部组织工艺/运维/采购/销售/质量部参与评审；市场项目不会调整大结构，一般不组织评审；
            5.  出二维图，设计人员自己出图，通过SW投影二维图，二维图可以直接调整，A0-A4都有。部分二维图出了装配图，不再出零件的二维图，直接在装配的二维图中表达；
            6.  出图样目录，通过SW导出二维图清单，手动删除外购件的所有自制和外协件；图幅自己在图样目录上输入，后期可能在图纸标题栏上直接体现，系统自动导出；图样目录为了查询纸质图纸，上系统后，可以不再出；
            7.  阶段标记，后续可能不再需要；
            8.  出明细表，进行审批，将纸质的传过去；
            9.  机型参数，通用的信息，为了定义到系统中便于查询；
            10. DFMEA质量程序文件/技术规范/招标技术要求的编制；
        4.  项目资料归档：
            1.  打印存档；
            2.  电子版本放自己电脑；
            3.  技术规范/招标技术要求等扫描放到共享服务器上；
    3.  变更：
        1.  图纸变更：图纸文件更改单
        2.  来源：现场反馈的问题/采购无法买到，需要调整适配/内部改进/降本等。
        3.  更改单编号，给资料员要编号；
        4.  根据编号起草内容（编写之前梳理变更的影响分析），发起审批流程（走研究所内部流程，线下与其他部门提前沟通好）；
        5.  修改图纸（二三维/纸质），发给其他部门；
        6.  质保发起不合格物料报废单和物料方案代用单，来进行更换物料；
    4.  SW版本与工艺不一致，设计用15，工艺用16；
    5.  采购在前期参与，会自己与供应商联系，邮件抄送采购；
    6.  对于外协的，采购定标，设计根据中标通知单联系供应商进行交互，基本通过邮件进行交互；
