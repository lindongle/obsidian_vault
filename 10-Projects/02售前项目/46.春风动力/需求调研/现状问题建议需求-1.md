1.  **公共知识：**
    1.  标准名称库
    2.  标准物料分类特征及物料唯一性校验条件；
    3.  标准件库（实例化含三维）/通用件库/优选库/材料库/元器件库（实例化，含符号/封装/三维）的统一管理及与设计工具的库集成，通用率的统计；
    4.  入库需要有申请流程，由专人进行维护；
    5.  项目交付物模板/变更单模板/二三维模板；
        1.  三维没有统一设计规范模板（如分层设计等），二维使用相同的标题栏；
        2.  其他标准规范文档，与KMS集成；
    6.  工艺资源库：
        1.  工装工具
        2.  辅料
        3.  工序库
        4.  工序数据库
    7.  标准化审核借助系统及设计工具进行自动化检查；
2.  **物料主数据：**
    1.  编号
        1.  编号上体现的信息太多，不方便管理，且体现需求越来越多；
        2.  编码位数不一致、不同业务码段规则也不一致，颜色件等（<span style='background:yellow;mso-highlight:yellow'>编码规则文档，标准件编码？</span>）；
        3.  对于子件数量较多的产品或总成，后四位种类号不够用（靠不上），规则扩展性不强，希望调整编码规则；
        4.  转V换号，导致转V时大量工作要进行调整，希望不再换号；
        5.  编码规则修订，目前体现信息太多且编码规则不统一，如常规零部件、工装工具、元器件、标准件等；
        6.  编码是否重复依赖人工多次尝试，影响设计效率；
    2.  物料申请及视图扩充：没有==物料申请过程，工程师直接给号==，走流程下发到SAP，同时BOM管理员BMP中发起视图收集流程，重新导入SAP进行视图扩充；
    3.  期望未来PLM中物料可以定义物料的采购/自制信息，并下发到SAP，其他MRP属性可设置默认；
    4.  希望能可以批量查询多个物料；
3.  **图文档：**
    1.  三维NX11为主，Catia部分，未来统一NX最新版本，或Catia转为NX格式交付，EDA统一Altium Designer 23；
    2.  部分物料没有三维模型，包括标准件/锁具等，难以识别BOM上缺少的物料信息，需要补充完善；
    3.  二三维部分没有关联，发动机NX/CAXA，发动机NX二维标注太慢；
    4.  二维数据格式不统一，且转PDF依赖手动，效率慢；
    5.  对于NX二维和三维目前为相同文件，未来进行拆分，便于单独浏览，希望历史数据可以批量进行转化；
    6.  二维图明细栏依赖手工编制，效率较慢，且变更后编号调整需要重新更新明细栏；
    7.  Caita原图不支持上传PLM，只能转为STP文件；
    8.  三维模型本地命名无规则，依赖自己习惯，转STP会按一定规则命名，未来考虑与物料名称相同；
    9.  缺少标准化和工艺审核节点，模型质量未有效监督，且工艺滞后，问题暴露时间晚；
    10. 发动机两套模型，一套内部使用，一套轮廓给到整机进行装配用，<span style='background:yellow;mso-highlight:yellow'>考虑未来系统中如何系统</span>；
    11. 文档按项目文件夹管理，历史版本数据缺失，且最新版本大都在工程师手中；
    12. 线上线下两套签字，重复流程，没有电子签字；
    13. 整机模型无法打开，希望尽快轻量化；
4.  **BOM：**
    1.  D/EBOM：
        1.  整车统一整机坐标系进行架构搭建，各专业设计自己的数据；
        2.  因前期（样机试制）变更太多，转V时才搭建上传PLM，设计BOM，前期数据无法协同；
        3.  包装在设计BOM中工程师搭建；
        4.  软件作为物料搭建在BOM中，管理软件的版本；
        5.  数据可导出到系统外部，便于编制其他项目交付物文档；
        6.  变形件：
            1.  目前只管理一种标准状态，实际为压缩状态等，会产生干涉；
        7.  硬件PCBA的BOM未在PLM中管理，希望未来可以展开到元器件层级；
        8.  DMU评审：
            1.  主要设计内部的评审，有单独的检查清单，未及时更新及有效共享；
            2.  总布置统一收集数据进行评审的组织；
            3.  工艺性审查过程缺失；
            4.  希望控制模型不符合标准时，无法发起流程，强制CheckMate；
    2.  P/MBOM：
        1.  整机辅料由BOM管理员在制造BOM中搭建，其他辅料及原材料在SAP中搭建；（==发动机设计及制造BOM均BOM管理员搭建？==）
        2.  制造BOM只体现了总装结构，其他半成品BOM没有在PLM中管理（如车架焊接或零件机加下级BOM由车间工艺搭建），上下游BOM不一致；
        3.  MBOM上一级部品拉平，没有中间层级（变更逐层换号影响小），与设计BOM结构不一致，相同物料数量也未合并；
        4.  制造BOM存在多工艺路线导致的多工厂MBOM情况，目前只搭建一个BOM，未来需扩展；
    3.  颜色件管理：
        1.  设计与制造BOM均体现白件（无色件）；
        2.  BOM上进行了颜色件的标识；
        3.  单独建立无色件与颜色的关系（无色件+4位颜色代码）；
        4.  存在电泳/喷涂多层结构，下游逐层换号；
        5.  下发SAP时，接口替换为颜色件（==如何确定替换的颜色？==）；
        6.  四轮内饰当前没有考虑<span style='background:yellow;mso-highlight:yellow'>纹理库</span>；
        7.  部分业务BOM中不体现颜色件，订单中进行处理（如新能源）；
    4.  备选件：
        1.  未维护备选件，均通过变更来执行，按需重新变更再替换回来，影响效率；
    5.  长周期采购BOM：
        1.  期望搭建长周期采购BOM，提前识别及下发SAP，目前SAP根据采购周期（2个月）自动跑需求；
    6.  KDBOM：
        1.  有业务，考虑二期实施；
5.  **协同设计：**
    1.  协同业务：
        1.  业务部门与基础数据管理部门（技术管理部）；
        2.  整机-零部件协同；
            1.  整机-发动机
            2.  整机-新能源/电智：
            3.  结构-电器/电控
        3.  机电软间协同；
        4.  系统架构；
        5.  设计与工艺等部门协同
            1.  模型的前期工艺性审查；
            2.  与工装的前期干涉性检查；
            3.  样机装车过程问题与设计的反馈流程；
        6.  与供应商协同
    2.  协同问题/需求：
        1.  协同间及业务部门内部不同专业的数据的权限的控制及共享；
        2.  MBSE相关方案数据在系统中文档管理及流程控制；
        3.  零部件转中间格式给到整车的交互过程；
        4.  目前PLM中数据与数据之前缺少关联性，发生问题难以追溯；
6.  **配置管理（整车/发动机）：**
    1.  数据字典/车型配置库由BOM管理员统一维护，超级BOM及变量条件由工程师维护；
    2.  配置条件在PLM中维护，具体选配及结算在SAP中进行；
    3.  配置平台规划划分标准正在建立，基本按车型为原则；
    4.  ==发动机选配精确产品如何给到整车-整车中发动机单独物料号，发动机产品本身只有型号==；
    5.  对于非订单选配车型，如电动自行车等，按转V时实际生产的车型，直接在SAP中给出精确整车编号，对于订单VC选配车型，如四轮等，在SAP中选配生成精确车型；
    6.  对于配置的调整，如增配，设计工程师希望只设计对应模型，具体配置由专人维护（当前职责问题，设计兼职，未来考虑独立）；
    7.  简化配置BOM变更的流程，如增配/车型配置更新等；
7.  **工艺设计：**
    1.  结构化工艺
        1.  产品BOP，但第一版根据车间实际情况设计，后续车间工艺人员自行调整，==分离结构化工艺和作业内容==；
        2.  总装工艺，组件分配根据车型进行选配，一套配置一套工艺，关联对应的工艺文件，转Excel表进行维护；
        3.  机加工艺，关联刀具及参数/设备工装/工序附图等；
    2.  工时管理：
        1.  目前工序为单位，前期估算，后面实际测算，未来规划细化到工步级别；
        2.  SAP中工艺路线及工时，主要为报工及财务核算，无生产指导意义，后续可能会代替（根据实际未来方案执行）；
    3.  工装/设备/工具管理：
        1.  工装申请过程；
        2.  工装设计（同设计）及干涉检查，不考虑系统中管控具体BOM及物料；
        3.  工装工具入库，管理整体工装/工具号；
        4.  结构化工艺工序的调用；
    4.  工艺文件
        1.  作业指导书，系统根据结构化工艺输出EWI文件基础上进行调整，部分装配考虑使用mockup进行动画录制，暂不应用C3D；
        2.  明细表等，系统自动汇总；
        3.  其他文件，如FMEA/控制计划等，作为文档管理；
        4.  CAM及机器人编程，文件交付传到系统，管理其版本及分部流程
    5.  问题/需求：
        1.  变更换号导致的工艺文件的不断更新，工作量大；
        2.  三维模型缺失，不缺的存在不准且重复的情况，导致工艺样机验证试装环节才发现问题，影响周期；
        3.  扭矩值等信息，设计可以提供的希望设计BOM上上直接维护后带到工艺BOP中；
        4.  建立标准工序库；
8.  **变更（技改）：**
    1.  量产前没有管理变更过程，也没有统计；
    2.  普通变更和紧急变更未能有效限制；
    3.  目前变更均换号，导致变更无延续性，且需要调整的文件/BOM等数据特别多，希望未来部分根据可互换性可以升版；
    4.  软件与硬件版本的统一性，新旧功能的追溯；
    5.  变更执行时，针对相互影响的数据，希望可以自动提醒道负责人；
    6.  问题流程与ECR评审流程、评审后验证及变更执行均在BPM中，只有修改设计数据后发布在PLM中，会单独创建更改单（批次号）；
    7.  希望变更评审时提供先后信息数据对比，并可以查询每个零部件的变更履历，目前系统换号，相对独立，无法追溯；
    8.  设计变更时只对影响车型及是否可互换进行评估，未对库存数据等信息进行统计，分析力度可能不足，希望变更分析时，可以查询物料的状态（在途/在制/在库）；
    9.  对于设计新版本数据在变更评审过程中修改及发布，最终更改执行主要下游执行为主，且基本不会退回；
    10. BOM更改手动在SAP和PLM都要执行更改，容易出现数据不一致；
    11. 变更流程较慢，业务环节多，且审核慢，希望可以提供审核时效表统计呆滞流程等，进行敦促提醒；
    12. 缺少变更相关流程及数据分析报表，后期可考虑BI系统集成；

    1.  SAP集成（MBOM/变更/长周期采购EBOM/库存查询）-T4S待定；
    2.  思普PLM集成（物料主数据，统一源头）；
    3.  数据发放集成（二三维/物料/BOM）；
    4.  BPM集成（文档/结构化数据/==流程节点？==）；
    5.  IAM集成（用户停启用）；
    6.  单点登录（域LDAP集成）；
    7.  IM（内网）/钉钉（外网）-消息通知；
    8.  NX/CATIA/AD；
    9.  KMS集成（文档/文件夹结构）；
