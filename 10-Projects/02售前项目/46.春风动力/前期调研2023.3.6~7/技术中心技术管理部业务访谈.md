时间：3月7日 PM 4:30~6:30
地点：213会议室
参会者：
春风：田主任、标准化工程师、BOM管理员；IT-郭经理；
西门子：蔡老师、李宏峰、孙毅等；
1.  思普系统设计BOM功能查看：
1.  产品型号创建，体现产品代号、产品型号、种类号、主配置、法规等信息 -- 相当于大房间；
2.  每个车型产品型号，针对不同法规会有多个主配置 -- 相当于小房间；
3.  每个主配置的小房间都需要定义配置代码，如：说明书（分组） -- 说明书_德语（内容）、制动不带ABS -- 相当于车型配置表，每次都要后台创建重复工作，没有配置字典的管理；由bom管理员维护；
4.  设计在搭建bom时，更改bom时可以展现完整层级；但在设计bom呈现时仅显示1级部品，可定义一级部品对应的配置定义（包含多列配置选择及颜色配置）； 配置bom上无法向下展开层级，设计使用不方便，也无法可视化展示三维形态，可以导出报表查看下级状态；由设计工程师维护变量条件；
5.  每个主配置的小房间都需要定义机型色彩和对应颜色件的颜色定义；期望是否可按照模板能快速搭建色彩库，不用每个挨个创建；
6.  机型色彩定义：整车颜色代号、整车颜色、颜色件图号、颜色件名称、零件色彩代号、零件色彩名称、备注；
2.  思普MBOM部品清单功能查看：
1.  添加发动机；
2.  添加辅料包：仅添加顶层，其下级由工艺在sap中补充维护；
3.  添加贴花总成：删除父级，提升子级别；
4.  剔除总成件提升采购级零件；需要导出表格找到子件，一级部品中删除父级，通过，编码查找子件再添加进去；
5.  有时候，一级的搭重了会检查并修改；
6.  添加配置代码的分组信息，传递给sap，用于销售在sap中选配驱动结算；
7.  添加部分配置用法，如：多种发动机的物料添加和配置条件；
8.  发动机单独开发有设计号，按配置开发；整车中使用物料号搭建（bom工程师申请料号），思普中不展开；
3.  试制BOM管理：
1.  试制bom线下Excel管理；
2.  标准件、借用件在sap中进量产库；专用件用Excel清单管理；
3.  试制bom冻结到转量产时有个时间差，期间如果借用量产的物料变更系统就会提示“有新品在用，但不知道哪些在用”，会出现变更遗漏。
4.  量产技改、试制技改是单独的，不关联，由工程师自己管控，可能会出现遗漏；即：被借用的件如果变更影响到批产车型、试制车型，需要出两个技改单贯彻，即：CR：CN，1:2；
4.  BOM现有问题&痛点探讨：
1.  【田主任】有部门反馈nx的3d转2d不好用？
2.  【田主任】墨西哥基地的物料包装不一样，物流不一样，价格也不一样？其物料号根据不同状态要都给号吗？
    1.  目前，由bom管理员在sap中根据不同工厂添加物料号；但潜在问题是技术状态变更时所有的派生的料号都会变？
    2.  每一个物料都需要包装
3.  【田主任】业务期望物料的编码中是否可以体现供应商信息？是否通过物料号识别？期望在sap中膨胀出物料号，可通过下游二维码扫码可以看到供应商信息？
4.  物料管理：标准件批量切换；关联件切换；会出现问题后，进行改造，比如：选A则必须装B，但设计没给定关联关系，生产端出错；
5.  BOM技改单，自动产生的差异报表非常不直观，信息不全且要对比查找，非常麻烦；
6.  零部件如果有尺寸和实物的状态的变化，则需要进行升级，即：换号；如果不影响实物状态和售后，则进行升版；大部分是升级换号；
7.  研发工程师无法直观查看到零部件的版本演变过程和数据；设计工程师无法快速查看到物料的变更的进度和状态，如：CR、CN、CN的变更阶段；
8.  变更管理：思普中通过管理批次号管理结果；在BPM中CO流程下游执行及管理断点执行切换；
    1.  描述变更原因等基本信息；
    2.  零部件：修改后的最新零部件信息；
    3.  变更单：图纸、bom变更点，纸质签审的扫描状态；
    4.  基本属性：变更接收部门、转量产执行状态；

5.  标准化管理：3人在编制；
    1.  企业技术标准体系的全生命周期管理；
        1.  每年根据企标的架构体系，定义要编制的企标，如：哪些空白？哪些修订？
        2.  相关部门（三电除外）进行标准编制；
        3.  线下组织会议评审，如果：偏业务方向的由相关关联部门参加；如果：管理办公室编制的基础标准，会覆盖较多部门；
        4.  评审通过后，OA上发布标准更新的通知；系统中进行挂在及共享；
    1.  具体规范在已上马的项目管理系统 -- 知识库模块管理；
    2.  目前，思普系统中也有一部分标准规范系统；
    3.  未来，会考虑上马专门的知识管理系统进行共享；
        5.  在正式发布前，会召开会议判断标准规范是否影响已有技术资料和图纸，会通过变更单方式进行贯彻和切换，标准化做好监督管理和跟踪；
        6.  问题&痛点：
    1.  标准体系架构不完善，即：类别之间的界限不明确；
    2.  设计部门相关的一些专用的指南等文件，由部门自己管理，但有些未上升到企业标准管理，需要逐步梳理好发布；
    2.  编码规则、图纸规范管理：
        1.  车型号（4位）-组号、分组号、顺序号（2、2、2）-种类号、序列号（2、2）-尾缀号（-Q1）-xxxxx（颜色等信息，SAP中专用）
        2.  管理批次号：202302133 -- 承载变更原因、体现哪些设计号和图纸，按此批次统一下发生效；
    1.  用于发布此部分数据的包，即为：批次号，类似于状态插旗的概念；
    2.  按照数据发布释放后，图纸即生效；
    3.  思普系统中没有数据状态的做法；

6.  EBOM属性配置维护进一步沟通： 目前，没有EBOM工程师，资深的DPL处理较流畅，新人会有问题；当前，多方都可以创建件号；
    1.  DPL：（执行车型）产品型号登记流程（思普系统）
    2.  标准化：创建车型基本信息；
    3.  DPL通过线下或钉钉等方式将该车型的主配置输入给标准化；
    4.  标准化：思普系统中创建该车型下的主配置；
        1.  主配置； -- 依据产品定义的配置，如：种类号； -- 某个车型下面的主配置，每种主配置会有个种类号（主要依据国家法规）；
        2.  类别号：E40；释义：E - 发动机；F - 整车；暂未考虑三电；
        3.  种类号：按车型平台为范围编制的种类序列号；（主要依据国家法规），如：5000、5100；
    5.  DPL通过线下或钉钉等方式将配件代码、配置代码输入给标准化；
        1.  配置代码（与车型关联，DPL维护==--必选的可选==）：内容、代号（DPL定义）、特征选用条件；如：车体腹板--CFW；警告贴花--EOO；个性贴花总成--T02--整车颜色
        2.  配件代码（与车型关联，DPL维护==--不必选的可选==）：代号、内容、分组（由BOM组维护）；-- 4位数字，如：E100；配件代码，可以有，也可以没有；
    6.  【EBOM工程师】探讨：
        1.  从吉利入职过来，提出过汽车行业的做法，有配置字典、配置语言、配置条件等规划的做法；
        2.  思考：
            1.  摩托车行业推进个性化；整车的做法是否适用于小批量多品种的模式？
            2.  吉利按行业中的整车架构结构VAS结构展开更规范、平台更规范、更快速的构建BOM，对摩托车是否使用？
7.  转V过程：按吉利的管理方法，通过零部件成熟度状态表达；
    1.  DPL在E1之前，线下给到转v工程师申请单（研发内部已经管控）作为触发；
    2.  【标准化】车型产品型号信息，将产品代号转v、产品状态从试制--\>量产；
    3.  【标准化】主配置信息，将产品代号转v；根据项目进度，如果1个车型下有多个主配置，会存在分时间段转主配置转v；即：1个大房间下面多个小房间；没有转v的小房间，先暂时修改不重复的种类号，带转v时再改回来，如：1000--9900--1000（自己记录对应号关系）；
    4.  【转V工程师】执行设计bom及技术资料转v；
        1.  【设计工程师】技术资料图纸转v；物料执行承认流程（思普流程）并发布，系统自动产生v号；
        2.  【标准化】思普设计bom转v，即：基于DPL的线下表格输入，重新查找并搭建bom；
        3.  【标准化】从OA发布转v通知；
        4.  问题：DPL熟悉bom情况；转v工程师无法确保bom的准确性；
    5.  【BOM工程师】执行MBOM转v；
        1.  基于ebom复制mbom并调整结构；（添加、提层等）
        2.  bpm发起审批流程；
【IT】接收通知，并执行发布功能将v状态的mbom发布给sap；==（如何实现mbom发布给sap，需补充询问）==
