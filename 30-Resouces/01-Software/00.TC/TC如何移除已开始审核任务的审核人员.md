# 1.说明

Teamcenter中发起工作流程后，当审签流程执行到审签任务节点时，默认情况下无法再添加或移除审签用户，由于TC中的审核任务是由选择审核人员和执行审签两个任务组合而成，当审核任务开始时，选择审核人员自动完成，所以无法再添加或移除审签人员，只能修改审签用户。本文主要用于指导系统实施或系统管理人员，对于已开始的审签任务，如果多添加了用户，如何移除多添加的用户。

# 2.审签任务问题（流程发起人）

流程发起人员发起审签流程后，例如流程到达标准化或会签任务节点，此时存在两个审签用户，由于工作安排或者人员选择问题，用户需要移除多余的审签用户。由于流程任务已经开始，默认情况下无法移除审签用户。

1）两个审签用户都未执行审签任务。需要移除其中一个未执行审签的用户。

2）两个审签用户其中一个用户已执行了审签任务。需要移除另一个未执行审签的用户。

# 3.查询签发（流程发起人或系统管理员）

签发signoff对象是TC系统中用于记录流程任务的签发用户的对象，与流程任务通过关系fnd0epmsignoff关联（其中流程任务为主引用，签发为次引用），首先由系统管理员在系统内查询构建器中配置查询签发，查询类型为signoff，如下图：

![[99-Assets/d206e2750888442c8a5d33db33f6f33c_MD5.png]]

由系统管理员或者流程发起者执行查询签发后，可以查询到签发对象，通过详细信息，可以查看签发关联的目标数据和流程信息，以确定需要删除的签发。

![[99-Assets/92799eee8a9c8725287c0a7735f96ef9_MD5.png]]

将签发对象发送至【我的Teamcenter】打开，在【影响分析】中查看引用关系，此处需要将选项WhereReferencedPOMPref的值设置为1，在影响分析中开启何处引用（POM）。

![[99-Assets/a06bf0f734067b69d02817017be34621_MD5.png]]

  

# 4.删除签发（流程发起人或系统管理员）

由系统管理员或流程发起人，将查询到的签发对象，发送至【我的Teamcenter】，

![[99-Assets/f7292b1fdbf808279ea1335629d82368_MD5.png]]

在影响分析中，通过【引用（POM）】（此处需要配置选项WhereReferencePOMPref，设置值为1，启用POM引用），查看签发引用关系，通常签发对象关联了选择审核人员、执行签发任务。

![[99-Assets/6fce8735005ac3b67e73c46f2427deb3_MD5.png]]

删除签发的引用关系，两个引用关系分别是选择审核人员和执行审签的引用关系。

![[99-Assets/6a3548d41be815a7047149da006bc2e2_MD5.png]]

引用关系删除后，再删除签发对象

![[99-Assets/794bbb5017d5b6e67310ca927ec211d7_MD5.png]]

  

# 5.更新任务状态（流程任务执行者）

经过上述4中删除签发处理后，即可删除不需要的签发用户，尽管签发列表中已经不再显示该用户，但是由于任务状态未更新，已删除用户的任务箱中还可以看到该任务，必须切换签发决定或执行任务才能刷新任务状态。

1）如果任务执行者还未开始执行审签任务，在发起人或系统管理员删除签发对象后，任务执行者再查看审签任务时，审签用户已发生变化。可以执行审签任务，任务状态会自动更新。

![[99-Assets/448f6677d335d323af5018ea1621b3f9_MD5.png]]

2）如果流程任务执行者已经执行过审签任务，在跟踪任务列表中，还可以查看到已经执行过的审签任务，审签人员信息已经发生变化。任务执行者可以再次点击该任务，切换任务的签发决定（此时可以重新选择签发决定）为不作决定，系统将刷新任务状态。并且用户执行批准或拒绝时的注释信息仍将保留。

![[99-Assets/4b8d16ab30986112ed2a58b6209406cd_MD5.png]]

例如用户之前执行了拒绝，可以再次点击拒绝，切换至不作决定，任务状态刷新后，可以再次重新执行拒绝。

![[99-Assets/9470b9faa08a2b477528093c300888fc_MD5.png]]

对于已经执行过批准或拒绝的用户，可以重新执行签发决定。

![[99-Assets/9e807acb32912bd4a4f461b0db8c33c7_MD5.png]]
