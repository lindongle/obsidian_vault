# 01 为什么选Obsidian

去年我的知识散落在五六个地方：飞书文档里放着电商运营资料，本地文件夹堆着AIGC提示词，微信收藏里塞着各种教程链接，浏览器书签栏已经溢出。每次找一个文件，要在三四个工具之间来回切换。

试过几个主流工具，都有硬伤：

| 工具 | 痛点 |
| --- | --- |
| Notion | 打开要等加载，批量导出后文件结构乱，数据在云端 |
| 印象笔记 | 免费版限制设备数量，广告越来越多，导出格式封闭 |
| 飞书文档 | 数据在服务器上，断网不能用，导出依赖官方工具 |
| 有道云笔记 | 免费版空间小，层级太深，搜索弱 |

最后选Obsidian，原因就一条：**所有笔记都是本地.md文件**。

这意味着四件事：

-   打开速度毫秒级，断网也能用
    
-   即使软件倒闭了，记事本照样能打开你的笔记
    
-   数据在自己硬盘上，不上传任何服务器
    
-   本地文件能用Git做版本控制——每次修改都有记录，误删了能恢复
    

> **一句话理解Obsidian：** 它不是一个记笔记的工具，而是一个个人知识管理系统。你记下的每条笔记都可以和已有知识建立连接，随着时间推移形成属于你自己的知识图谱。

# 02 下载安装与创建仓库

## 下载安装

打开<u>https://obsidian.md/</u>，下载对应系统的安装包。

![[99-Assets/1926852561fb312763fe674cde968ae1_MD5.png]]

**Windows：**下载.exe文件，双击安装，不需要配置环境变量，整个过程不到3分钟。安装路径建议选非C盘。

**macOS：**下载.dmg文件，将Obsidian图标拖入Applications文件夹。首次打开时右键选择"打开"，点击"仍要打开"绕过安全提示。

**移动端：**iOS在App Store搜索"Obsidian"下载，Android在Google Play下载或从官网下载APK。

> **注意：** 一定从官网obsidian.md下载，不要从第三方下载站获取，第三方安装包可能捆绑恶意软件。

## 创建仓库

安装完成后第一次打开，Obsidian会显示仓库选择界面。仓库（Vault）本质上就是电脑上的一个文件夹，里面存放你所有的Markdown笔记。

**操作步骤：**

1.  点击\*\*"Create new vault"\*\*（创建新仓库）
    
    ![[99-Assets/e497d63b3a1fc08ef267c65775dac017_MD5.png]]
    
2.  在Vault name输入仓库名称（比如"我的知识库"）
    
    ![[99-Assets/ea987d0c3bb511cf2a4a07a76caee85e_MD5.png]]
    
3.  点击Browse选择存放位置（建议选一个容易找到的路径，比如`E:\Obsidian\我的知识库`）
    
4.  点击**创建**
    

> **最佳实践：** 新手只用一个仓库管理所有笔记。用文件夹和标签来分类，而不是建多个仓库。这样双向链接和全局搜索才能把所有知识串联起来。

仓库文件夹里有一个隐藏的.obsidian文件夹，存放设置、插件配置、主题等信息。你的笔记.md文件直接以明文存在仓库中。**把整个仓库文件夹拷走，就是完整的备份。**

# 03 界面认识与关键设置

## 界面布局

打开Obsidian后，从左到右分为几个区域：

-   **左侧边栏：** 文件管理器（浏览笔记文件）、搜索、书签
    
-   **编辑区（中央）：** 你写笔记的主区域，支持多标签页打开多个笔记
    
-   **右侧边栏：** 反向链接、大纲、本地关系图谱
    
-   **底部状态栏：** 字数统计、编辑/预览模式切换、同步状态
    

## 安装后立刻改的3个设置

**设置一：默认视图改为编辑视图**

设置 → 编辑器 → 默认视图改为"编辑视图"。这样打开笔记直接进入编辑状态，不用每次手动切换。

**设置二：链接格式改为相对路径**

设置 → 文件与链接 → 新链接格式改为"相对文件路径"。默认存放位置改为"当前文件夹"。相对路径在仓库迁移时不容易出问题。

**设置三：切换中文界面**

设置 → 通用 → 语言下拉菜单中选择"简体中文"。修改后Obsidian会提示重启，点击重启即可。

## 编辑模式

Obsidian有两种编辑模式：

-   **源码模式：** 显示原始Markdown语法，适合熟悉Markdown的用户
    
-   **实时预览模式：** 所见即所得，输入`**加粗**`立即显示为**加粗**
    

切换方法：按Ctrl+E在两种模式间切换。新手建议直接用实时预览模式。

# 04 Markdown基础语法

Obsidian使用Markdown语法——一种用纯文本标记格式的语言。掌握下面这些基础语法，就能写出排版漂亮的笔记。

## 标题层级

用#号表示标题，数量代表层级：

```sql
# 一级标题
## 二级标题
### 三级标题
#### 四级标题
```

## 文本格式

| 语法 | 效果 | 说明 |
| --- | --- | --- |
| `**加粗**` | **加粗** | 两个星号包裹 |
| `*斜体*` | 斜体 | 一个星号包裹 |
| `～～删除线～～` | 删除线 | 两个波浪线 |
| `==高亮==` | \==高亮== | Obsidian专属语法 |
| `` `行内代码` `` | `代码` | 反引号包裹 |

## 列表

```sql
无序列表：
- 第一项
- 第二项
- 子项目（缩进两格）
- 第三项

有序列表：
1. 第一步
2. 第二步
3. 第三步

任务列表（Obsidian专属）：
- [ ] 待办事项
- [x] 已完成事项
```

## 双向链接

```sql
[[笔记名]]          链接到另一篇笔记
[[笔记名|显示文字]]  用自定义文字替代笔记名
[[笔记名#标题]]      链接到某篇笔记的特定标题
![[笔记名]]          嵌入（直接显示）另一篇笔记的内容
```

## 图片

```sql
![[图片文件名.png]]    Obsidian专属，自动从仓库中找图片
![描述文字](https://mp.weixin.qq.com/%E5%9B%BE%E7%89%87%E8%B7%AF%E5%BE%84)   标准Markdown语法
```

> **效率技巧：** 不用死记这些语法。在实时预览模式下，直接用快捷键：`Ctrl+B`加粗、`Ctrl+I`斜体、`Ctrl+K`插入链接。或者输入`/`触发快捷命令菜单。

# 05 核心功能实战

## 双向链接 — Obsidian的灵魂

在任何笔记中输入\[\[，Obsidian会弹出搜索框，列出仓库中所有笔记。选择一个笔记名，就创建了一个双向链接。被链接的笔记底部会自动生成反向链接区域，显示谁引用了它。

**实际用法：**假设你有一篇笔记叫"时间管理方法"，在今天的日记里写今天学习了\[\[时间管理方法\]\]。此时在"时间管理方法"这篇笔记底部，会自动出现"被以下笔记引用：今天的日记"。不用手动维护引用关系。

## 标签系统

在笔记任意位置输入#标签名就能添加标签。标签在Obsidian中是全局的，可以在左侧"标签面板"中按标签筛选笔记。

-   `#工作`
    
    — 单级标签
    
-   `#工作/项目A`
    
    — 嵌套标签（自动形成层级）
    
-   `#工作/项目A/会议`
    
    — 多级嵌套
    

> **标签 vs 文件夹：** 一篇笔记只能在一个文件夹里，但可以打无数个标签。用文件夹做大分类，用标签做交叉维度。比如笔记放在"项目A"文件夹，同时打
> 
> ```sql
> #紧急
> #会议记录
> #待跟进
> ```
> 
> 等标签。

## 关系图谱

按Ctrl+G打开全局关系图谱，所有笔记以节点形式呈现，双向链接变成连接线，形成一张知识网络图。拖动节点重新排列，滚轮缩放，点击节点直接跳转到笔记。

![[99-Assets/784c4fcaef4ae7a5d3be7064b7fe2804_MD5.png]]

局部图谱在右侧边栏打开，只显示当前笔记的关联关系，更聚焦。随时间推移，图谱会越来越丰富——这是你的知识增长的可视化。

## 搜索功能

按Ctrl+Shift+F打开全局搜索。Obsidian的搜索支持：

-   `path:文件夹名`
    
    — 只在指定文件夹中搜索
    
-   `tag:#标签名`
    
    — 搜索特定标签的笔记
    
-   `file:文件名`
    
    — 按文件名搜索
    
-   `"精确短语"`
    
    — 用引号包裹进行精确匹配
    
-   `line:(词1 词2)`
    
    — 同一行中包含多个词
    

## 模板功能

如果你经常写格式相似的笔记（日记、会议记录、读书笔记），模板能大幅提升效率。

1.  在仓库中新建一个文件夹（比如`Templates`），在里面创建模板笔记
    
2.  `设置 → 核心插件 → 开启"模板"`
    
    ，指定模板文件夹路径为`Templates`
    
3.  在任意笔记中按`Ctrl+P`打开命令面板，输入"模板"，选择"插入模板"
    

模板中可以使用变量：{{date}}自动插入日期、{{time}}插入时间、{{title}}插入笔记标题。

## 常用快捷键速查

| 功能 | Windows | macOS |
| --- | --- | --- |
| 新建笔记 | Ctrl+N | Cmd+N |
| 命令面板 | Ctrl+P | Cmd+P |
| 全局搜索 | Ctrl+Shift+F | Cmd+Shift+F |
| 编辑/预览切换 | Ctrl+E | Cmd+E |
| 关系图谱 | Ctrl+G | Cmd+G |
| 加粗 | Ctrl+B | Cmd+B |
| 斜体 | Ctrl+I | Cmd+I |
| 插入链接 | Ctrl+K | Cmd+K |
| 打开设置 | Ctrl+, | Cmd+, |

# 06 接入AI：让知识库能对话

Obsidian本身只是一个Markdown编辑器，真正让它变成"第二大脑"的是AI插件。我实测了三种接入方式，各有适用场景。

## 方案一：Copilot for Obsidian（推荐入门）

Copilot是目前Obsidian生态最成熟的AI对话插件，由Logan Yang维护，支持OpenAI、Anthropic Claude、Google Gemini、Ollama等多种模型。

**安装方式：**设置 → 第三方插件 → 关闭安全模式 → 浏览 → 搜索"Copilot" → 安装 → 启用

![[99-Assets/ce4d97c75b6c14690a03a91285a7c8ff_MD5.png]]

**核心能力是Vault QA（知识库问答）：**你在聊天框里提问，Copilot会从你的笔记中检索相关内容，然后基于这些内容生成回答。比如我问"WB电商的佣金政策是什么变化"，它会从我之前写的电商笔记里找到相关信息并总结。

**配置步骤：**

1.  安装并启用Copilot插件
    
2.  在插件设置中填入你的API Key（OpenAI、Anthropic等任选）
    
3.  在聊天面板中选择"Vault QA"模式
    
4.  提问，插件自动跨笔记库检索相关笔记并回答
    

如果不想用云端API，Copilot也支持本地模型。安装Ollama后，在Copilot设置里把模型提供者选为Ollama，填入本地地址http://localhost:11434，选择模型（如llama3.2），就能完全离线运行。数据不出本机，隐私零风险。

## 方案二：Smart Connections（语义关联推荐）

Smart Connections是Obsidian生态中用户量最大的AI插件，截至2026年中已超过100万下载量。它的工作原理是：将每条笔记切分为块，用嵌入模型为每个块生成向量，然后计算笔记之间的语义相似度。

**安装方式同上，**在插件市场搜索"Smart Connections"。

它的妙处在于发现你意想不到的关联。比如我在写"AIGC提示词编写原则"时，它推荐了"电商与广告提示词"——因为两者都涉及"清单型优于氛围型"这个共同原则。这种跨领域的连接，是手动打标签做不到的。

![[99-Assets/dd3f1ae1d0726896d98eeed2f3a5a27e_MD5.png]]

2026版已模块化拆分，核心功能（语义推荐）完全免费，本地嵌入，不需要API Key。另外还有Smart Chat（将AI对话附着在笔记上）、Smart Graph（语义聚类可视化）等子插件。

## 方案三：用AI编程工具批量整理笔记（进阶）

如果你在用Trae、Cursor这类AI编程工具，可以让AI直接操作本地的Markdown文件，实现笔记的批量整理和迁移。

![[99-Assets/b442fb599cdb52d1c6d546441304d3e5_MD5.png]]

![[99-Assets/2dee1c20dba91682264c88cf0ff71d1d_MD5.png]]

思路很简单：Obsidian的笔记就是普通.md文件，AI编程工具可以读写本地文件，所以可以用Python脚本让AI帮你做这些事——读取散落在各处的源文件，提取知识点，生成带frontmatter、双向链接和标签的Obsidian笔记。

我用这个方法把55篇笔记从分散的文件夹整理到了知识库中。AI负责读取源文件、提取知识点、生成符合Obsidian格式的笔记，整个过程比手动操作快了至少10倍。

**具体做法：**让AI写一个Python脚本，扫描你的源文件目录，按内容分类，为每个文件生成标准的Obsidian笔记（含YAML frontmatter和\[\[\]\]双向链接），然后批量写入到知识库对应的子文件夹中。

这个方案不需要安装额外的Obsidian插件，任何能读写文件的AI工具都能做。门槛比前两个高一些，但适合需要一次性迁移大量内容的场景。

## 三种方案对比

| 维度 | Copilot | Smart Connections | AI编程工具批量整理 |
| --- | --- | --- | --- |
| 核心能力 | 对话式问答 | 语义关联推荐 | 批量读写文件 |
| 数据流向 | 可选云端或本地 | 本地索引 | 本地操作 |
| 上手难度 | 低 | 低 | 中 |
| 适合场景 | 查询知识库 | 发现关联 | 知识库迁移和整理 |
| 费用 | 免费（自带API Key） | 免费 | 免费 |

三个方案可以同时使用，互不冲突。Copilot负责对话，Smart Connections负责推荐，AI编程工具负责批量操作。

> **插件使用建议：** 新手不要一上来就装几十个插件，会拖慢启动速度且增加学习负担。建议先装Copilot一个，用熟了再按需添加。

# 07 GitHub自动同步：零成本的多端备份

本地文件的最大隐患是设备丢失或硬盘损坏。用GitHub做自动同步，一分钱不花，还能获得版本控制能力——每次修改都有记录，误删了能恢复到任意历史版本。

## 第一步：创建GitHub私有仓库

登录GitHub，点击右上角+ → New repository。仓库名随意（比如obsidian-vault），可见性务必选**Private**。初始化时不要勾选README，保持空仓库。

## 第二步：安装Obsidian Git插件

在Obsidian中：设置 → 第三方插件 → 浏览 → 搜索"Git"→ 安装 → 启用

![[99-Assets/981e024b26ffa41b15e5046b4d6cbd7c_MD5.png]]

## 第三步：初始化Git并连接GitHub

1.  按`Ctrl+P`打开命令面板，输入`Git: Initialize a new repo`，回车
    
2.  再次按`Ctrl+P`，输入`Git: Add remote`，填入GitHub仓库地址（SSH格式：`git@github.com:用户名/仓库名.git`）
    

> **Windows找不到Git的解决方法：** 系统提示找不到Git时，需要手动指定路径。在插件设置里的"Custom Git binary path"中填入`C:\Program Files\Git\cmd\git.exe`。新开的终端能用`git`命令，但已经打开的终端可能需要重启才能识别。

## 第四步：配置自动同步

在Obsidian Git插件设置中，配置以下选项：

| 设置项 | 推荐值 | 说明 |
| --- | --- | --- |
| Auto commit-and-sync interval | 15 | 每15分钟自动提交并同步 |
| Commit message template | `vault backup: {{date}}` | 自动生成提交信息 |
| Auto pull on startup | 开启 | 打开Obsidian时自动拉取最新 |
| Pull before push | 开启 | 推送前先拉取，避免冲突 |
| Show status bar | 开启 | 底部状态栏显示同步状态 |

配置完成后，状态栏会显示一个Git图标和当前分支。以后你只管写笔记，插件每15分钟自动提交一次推送到GitHub。

> **常见问题：** 如果设置了自动同步间隔但没生效，检查插件设置中是否有"Auto commit-and-sync interval (minutes)"这个字段。不同版本字段名可能不同，手动填入数字即可。

## 第五步：配置.gitignore

在仓库根目录创建.gitignore文件，排除不需要同步的文件：

```sql
.obsidian/workspace.json
.obsidian/graph.json
.trash/
```

workspace.json包含窗口布局和打开的标签页，每台设备布局不同，同步会互相覆盖。graph.json是关系图谱的视图设置，同理不需要同步。

> **仓库体积控制：** GitHub免费仓库有1GB容量和100MB单文件限制。如果在笔记里放了大量图片，仓库会迅速膨胀。建议图片存放在外部图床，笔记里只放Markdown文本和必要的截图。

# 08 手机端同步方案

电脑端配好GitHub同步后，手机上也有几种方案，按需求和预算选择。

## 方案一：Obsidian官方Sync（省心但付费）

官方Sync每月8美元（约60元人民币），手机端零配置——登录同一个账号，笔记自动出现在手机上的Obsidian App里。支持端到端加密，版本历史保留30天（8美元档）或12个月（10美元档）。

不想折腾、手机上又要频繁看笔记的人，这笔钱花得值。

## 方案二：iOS用Working Copy + Obsidian

iPhone上用Working Copy（付费App）克隆GitHub仓库，然后把仓库文件夹链接到Obsidian的仓库目录。手机上编辑的笔记通过Working Copy推送回GitHub，电脑端自动拉取。

操作流程：Working Copy克隆仓库 → 在Obsidian中打开该仓库文件夹 → 编辑笔记 → 回到Working Copy提交推送。

比直接在Obsidian里跑Git插件稳定得多——Obsidian Git插件在iOS上偶尔会出问题，尤其系统更新后。

## 方案三：Android用Termux + Git

Android上通过Termux安装Git，把仓库克隆到本地，然后用Obsidian打开。或者用FolderSync这类App，把GitHub仓库同步到本地文件夹。

## 方案四：iCloud / Google Drive（最简单但无版本控制）

不需要版本控制、只是想在手机上看笔记的话，直接把Obsidian仓库放在iCloud Drive（iOS）或Google Drive（Android）的同步文件夹里。Obsidian移动版支持直接打开云盘中的仓库文件夹。

零配置，但失去了Git的版本历史和冲突管理能力。偶尔在手机上查看笔记、不怎么做编辑的人够用了。

## 四种方案对比

| 方案 | 费用 | 版本控制 | 上手难度 | 适合场景 |
| --- | --- | --- | --- | --- |
| 官方Sync | 8美元/月 | 有（30天/12个月） | 极低 | 频繁在手机上编辑 |
| Working Copy | App付费 | 有（永久） | 中 | iOS用户+需要Git |
| Termux + Git | 免费 | 有（永久） | 高 | Android技术用户 |
| iCloud/Google Drive | 免费 | 无 | 极低 | 只在手机上看笔记 |

# 09 知识库组织：MOC索引结构

笔记多了之后，最怕的不是找不到某一篇，而是不知道自己有哪些。MOC（Map of Content）是解决这个问题的最佳实践。

MOC的核心思路：为每个知识领域创建一篇索引笔记，列出该领域下的所有笔记及其简要说明。所有MOC再汇总到一篇首页MOC中。

## 推荐的文件夹结构

```sql
知识库/
├── 首页 MOC.md          ← 总入口
├── 02-公众号/
├── 03-AIGC创作/
│   ├── 图片提示词/
│   ├── 视频提示词/
│   ├── 工具笔记/
│   ├── 项目复盘/
│   └── AIGC创作 MOC.md   ← 领域索引
├── 04-电商运营/
├── 05-个人/
├── 06-开发项目/
├── 07-创作规则/
└── Templates/            ← 模板文件夹
```

数字前缀的作用是控制排序，让常用文件夹排在前面。"收件箱"模式的核心是：新笔记先丢进一个临时文件夹，定期整理到对应位置，避免分类焦虑。

## 每篇笔记的标准格式

笔记头部使用YAML frontmatter标注标签和更新时间：

```sql
---
tags: [AIGC, 图片提示词, 即梦]
updated: 2026-08-10
---
```

笔记之间用双向链接连接。比如在"AIGC创作 MOC"中写\[\[AI图像提示词精华库\]\]，Obsidian会自动识别这是一个链接，点击跳转。如果目标笔记不存在，链接会显示为灰色，点击直接创建。

## MOC索引笔记示例

```sql
# AIGC创作 MOC

## 图片提示词
- [[AI图像提示词精华库]] — 清单型提示词编写原则和实例
- [[电商主图提示词模板]] — 电商场景专用模板

## 视频提示词
- [[短剧创作最高标准要求]] — AI短视频的质量标准
- [[光武大帝项目复盘]] — 完整项目流程拆解

## 工具笔记
- [[HyperFrames视频合成框架]] — HTML视频合成工具
```

这套结构的好处是：从首页出发，最多两次点击就能到达任何一篇笔记。AI插件检索时，MOC笔记提供了全局上下文，帮助AI更准确地定位信息。

# 10 实操踩坑与避坑清单

以下都是我亲自踩过的坑，附解决方案。

**Git路径问题。**Windows上安装Git后，git命令在终端可用，但Obsidian Git插件可能找不到。需要在插件设置里手动填写完整路径C:\\Program Files\\Git\\cmd\\git.exe。新开的终端能用git命令，但已经打开的终端可能需要重启才能识别。

**中文编码问题。**用脚本批量创建笔记时，PowerShell默认编码可能不是UTF-8，导致中文乱码。解决方案是在写入文件时显式指定编码：\[System.IO.File\]::WriteAllText(path, content, \[System.Text.Encoding\]::UTF8)。

**插件自动同步间隔不生效。**Obsidian Git插件有个旧版字段名问题，自动同步间隔的设置项名称在不同版本中可能不同。如果设置了间隔但没生效，检查插件设置中是否有"Auto commit-and-sync interval (minutes)"这个字段，手动填入数字。

**仓库体积膨胀。**如果在笔记里放了大量图片，GitHub仓库会迅速膨胀。建议图片存放在外部图床或单独的Git LFS仓库中，笔记里只放Markdown文本和必要的截图。

**手机端Git冲突。**同时在电脑和手机上编辑了同一篇笔记，推送时会产生合并冲突。解决方法：养成编辑前先拉取的习惯。电脑端配了Auto pull on startup，手机端用Working Copy的话，打开仓库前先pull一次。

**不要一开始就追求完美结构。**先用起来，结构在使用中自然演化。我最初只建了两个文件夹，用了两周后才根据实际内容逐步细化到现在的结构。

**不要装太多插件。**先掌握核心功能，插件按需添加。装了50个插件才发现真正好用的就那几个。建议先装Copilot一个，用熟了再按需添加。

**不要只记不链。**孤立笔记没有价值。每条新笔记尽量和已有笔记建立至少一个双向链接，哪怕只是\[\[相关主题\]\]这样一个链接。

# 11 最短上手路径

如果你已经看到这里，说明你确实需要一个能长期使用的知识管理工具。有两条路径，选适合你的。

## 路径A：在AI客户端里用Obsidian CLI（推荐，不改变习惯）

如果你已经在用Trae、Cursor这类AI客户端，不需要学Obsidian的操作界面，用CLI直接让AI帮你管理知识库。

1.  下载Obsidian → 创建仓库（5分钟，见第02章）
    
2.  开启Obsidian CLI：`设置 → 通用 → 高级 → 命令行接口`，开启后CLI会自动注册到系统PATH
    
3.  在AI客户端中安装Obsidian CLI连接器（如Trae的codex-obsidian插件）
    
4.  直接在AI客户端里对话操作：搜笔记、建笔记、整理笔记、建双向链接——AI通过CLI读写你的知识库
    
5.  可选：配GitHub同步做备份（见第07章）
    

整个过程约15分钟，不用学Markdown语法，不用记快捷键，不用切换工具。你在熟悉的AI对话界面里说"帮我搜一下之前记的佣金政策"，AI直接从知识库里翻出来。说"把这段整理成一篇笔记存进去"，AI自动生成标准格式写入对应文件夹。

Obsidian后台开着就行，你甚至不需要打开它的界面。知识库的笔记是本地.md文件，随时可以用任何编辑器打开。

## 路径B：在Obsidian里直接用（适合想完整体验的人）

如果你想深入了解Obsidian的全部功能，按这个顺序走：

1.  下载Obsidian → 创建仓库 → 写第一篇笔记
    
2.  按`[[`打出第一个双向链接
    
3.  `设置 → 第三方插件 → 关闭安全模式 → 安装Copilot`
    
    → 填入API Key → 提问
    
4.  GitHub创建私有仓库 → 安装Obsidian Git插件 → 配置15分钟自动同步
    
5.  建一个"首页 MOC.md" → 把现有笔记用`[[]]`链接起来
    

整个流程走完大约1小时。之后就是持续往里填内容，笔记这个东西，早一天开始，早一天复利。

## 两条路径对比

| 维度 | 路径A（AI客户端+CLI） | 路径B（Obsidian原生） |
| --- | --- | --- |
| 配置时间 | 约15分钟 | 约1小时 |
| 学习成本 | 几乎为零 | 需学Markdown和快捷键 |
| 改变习惯 | 不改变，留在AI客户端 | 需要适应新工具 |
| AI能力 | 通过CLI完整读写知识库 | 通过Copilot插件对话 |
| 适合谁 | 已在用AI客户端的人 | 想完整体验Obsidian的人 |

两条路径殊途同归：知识库都是同一批本地.md文件。路径A先用起来，之后想体验Obsidian原生功能，随时打开Obsidian界面即可——数据完全互通。
