<span style='font-size:10.5pt;color:#333333;background:#F3F8FE'>汽车工业面临由机械机器向电子产品过渡的新变局，</span><span style='font-weight:bold;font-size:13.5pt;color:#346CDD;background:#F3F8FE'>汽车软件</span><span style='font-size:10.5pt;color:#333333;background:#F3F8FE'>成为未来汽车构架重要组成部分。</span>

<span style='font-family:-apple-system;font-size:9.0pt;color:#888888;background:white'>◎ 文/ 深圳联友科技有限公司 余慧</span>  

<span style='background:white'>传统车型上有发动机、自动变速箱、ABS系统、车载娱乐影音系统、四轮驱动扭矩分配系统、主动悬挂系统、安全气囊+安全带系统等上百个ECU（Electronic Control Unit 电子控制单元），而在未来的集成化计算单元体系下，软件的重要性将愈发凸显，与ECU配合定义汽车功能，涵盖操作系统、基础软件以及其他应用软件的车载软件，造车壁垒已经由从前的上万个零部件拼合能力演变成将上亿行代码组合运行的能力。</span>

<span style='background:white'>同时，汽车行业也面临盈利挑战，商业模式发生调整，从整车盈利逐渐向售后服务盈利、软件服务盈利转变，如特斯拉已构筑初阶车企软件盈利模式。</span>

<span style='background:white'>软件作为汽车产品越来越重要的构成部分，如何精确高效的管理好车型、软件版本、硬件版本之间的关联关系，如何支持整车盈利模式想软件服务盈利模式的转变，已成为企业产品数据管理需要考虑的关键课题。笔者认为，</span><span style='font-weight:bold;background:white'>将软硬件统一纳入企业级BOM管理平台，可确保软硬件版本数据的配套性，为生产、售后刷写提供准确的数据支持，为软件更新升级提供准确性、安全性保障，为软件服务盈利提供数据支持。</span>

<span style='font-weight:bold;background:white'>01</span>

## <span style='color:#2E75B5;text-align:center'>什么是软件BOM管理？</span>

<span style='background:white'>BOM是表示产品的物料构成，传统的汽车产品BOM通常是指硬件物料的构成，那么软件也是产品的构成部分，将软硬件关联一并纳入企业级BOM平台进行一体化管理，为企业提供全面产品数据管理，为生产刷写，售后服务提供精确的软件数据服务。</span>

<span style='background:white'>对于一个整车产品来说，其物料构成既有硬件又有软件，软件可作为物料的一种类型进行管理，软件类型又细分为：</span><span style='font-weight:bold;background:white'>控制程序、标定文件、配置参数</span><span style='background:white'>等，如图1。</span>

![image3](e18f62975eed4c93b68d1bbeb0948620.png)

<span style='font-style:italic;text-decoration:underline;background:white'>图1 将软件作为物料的一种类型进行管理</span>

«span style='background: \#F2F2F2'»本文中重点阐述软件管理的要点，不对硬件BOM的管理进行展开。«/span»

<span style='font-weight:bold;background:white'>02</span>

## <span style='color:#2E75B5;text-align:center'>软件管理的重要性 </span>
<span style='font-weight:bold; font-family:-apple-system;background:white'>2021年1月22日，软件更新法规UN R156（软件升级及软件升级管理系统）正式生效。</span><span style='font-family:-apple-system;background:white'>2021年6月28日，欧盟汽车专家组提交了Regulation (EU) 2018/858和Regulation (EU) 2019/2144关于软件更新的修订法规草案。在Regulation (EU) 2019/2144修订草案中，</span><span style='font-weight:bold;font-family:-apple-system;background:white'>UN R156软件更新法规与UN R155网络安全法规共同成为D4防护车辆网络攻击的技术法规，于2022年7月开始实施。</span><span style='font-family:-apple-system;background:white'>Regulation (EU) 2018/858修订草案中则在Anne IV-COP程序正文新增了第5段，要求制造商的软件更新管理系统SUMS及车型必须符合UN R156法规。</span>

<span style='background:white'>随着汽车软件相关法规政策推出，软件BOM管理愈发重要，将覆盖从研发、生产到售后全生命周期，涉及软件的原始版本、更新版本、相关硬件版本、对认证参数的影响管理等等。</span>

<span style='font-weight:bold;background:white'>03</span>

<span style='font-weight:bold;background:white'>软件BOM与软件全生命周期管理（ALM）</span>

<span style='font-weight:bold;background:white'>的区别与侧重点</span>

<span style='background:white'>软件管理包括</span><span style='font-weight:bold;background: white'>软件的开发管理</span><span style='background:white'>、</span><span style='font-weight:bold;background:white'>软件BOM管理</span><span style='background: white'>、</span><span style='font-weight:bold;background:white'>软件刷写</span><span style='background:white'>三部分业务。</span>

<span style='background:white'>软件生命周期管理（ALM）通常是指软件的产生直到报废或停止使用的生命周期，侧重的是软件的开发管理，即软件本身的产生过程管控，包括需求定义、可行性分析、总体描述、系统设计、编码、调试和测试、验收与运行、维护升级到废弃等阶段。</span>

<span style='background:white'>而本文的中探讨的软件BOM管理则侧重软件对象与车型、硬件的关联关系、版本管理、追溯管理，</span><span style='font-weight:bold;background:white'>只有软件BOM实现了精准管理，才能精确的提取每一辆车不同ECU在不同阶段应该刷写的正确软件版本。</span>

<span style='background:white'>不论是在哪个阶段或是哪种刷写方式（预装刷写、生产线刷写、售后刷写、OTA升级），对于软件刷写来说，都是基于软件BOM提供的准确软件版本，通过刷写设备或者OTA升级方式将软件写入到ECU中。</span>

<span style='background:white'>汽车软件相对其他软件来说安全要求更高，那么软件刷写版本的准确性尤为重要，而软件BOM管理根本目的就是确保车辆、硬件版本与软件版本关联的准确性，确保每一辆车、每个ECU从车辆组装到售后服务过程中任何时候都精准获取相应的软件版本。</span>

<span style='font-weight:bold;background:white'>04</span>

<span style='font-weight:bold;background:white'>软件管理的关键课题</span>

<span style='color:#346CDD;background:#F2F2F2'>◉ </span><span style='color:#333333; background:#F2F2F2'>ECU软件升级快、版本多，并且与ECU硬件的变更往往不同步。软硬件版本如何配套关联管理，支持准确刷写、软件追溯。</span>

<span style='color:#346CDD;background:#F2F2F2'>◉ </span><span style='color:#333333; background:#F2F2F2'>同一个ECU单元用于不同配置的车型，ECU控制参数有差异，如何高效的进行差异化参数管理。</span>

<span style='color:#346CDD;background:#F2F2F2'>◉ </span><span style='color:#333333; background:#F2F2F2'>软件更新如何有效管理。</span>

<span style='background:#F2F2F2'>本文后续将对这些课题一一探讨。</span>

## <span style='color:#3F3F3F'>1、硬件、软件关联管理目前常见做法</span>
## <span style='color:#2E75B5'> </span>

<span style='background:white'>不同于以前依靠多个 ECU 由零部件供应商主导的软件产品概念时代，主机厂愈发需具备软件的管理能力及核心软件设计能力，但目前仍然存在大量主机厂依赖硬件供应商提供相关软件，尤其是传统燃油车企业，大多数汽车主机厂当前处于自主和外购两者并存的混合模式，</span><span style='font-weight:bold;background:white'>不论是哪种模式，主机厂都需要对自主和外购的软件进行管理，软件的管理能力关系到软件刷写、售后诊断、软件升级的高效和准确性。</span>

<span style='background:white'>对于软件不同的供货模式（自主or外购），为了软件管理的便利性，可由不同BOM结构搭建方式。</span>

<span style='background:white'>外购软件，通常随硬件同步供货，是由供应商将软件灌装好后，再以ECU总成形式供货给主机厂，可以将软件和硬件（壳体、PCB板等）平行挂接在总成下，如下图3。</span>

![image5](f5e240e0605e4ca99bb9db07aea1e2a4.jpg)
<span style='font-style:italic;text-decoration:underline;font-family:-apple-system; font-size:10.0pt;color:#888888;background:white'>图3 对于外购软件将软件和硬件平行挂接在总成下</span>  

<span style='background:white'>作为研发部门来说，将软件也纳入BOM中进行统一管理，当软件发生变更的时候，可根据软件变更的互换性来对软件进行升版或者换号，相应的ECU总成件可保存不变、或升版、或换号。而对于制造、采购、生产部门来说，只需要针对EUC总成件进行制造管控，将EUC总成件定义为采购单元（ECU以下零部不再划分路线），采购依据采购单元进行采购管理和采购执行，并根据软件版本要求验货。</span>

<span style='background:white'>ECU虽然已经由供应商预装好，但是对于已经预装的ECU来说，将会被装配到不同的车型上，为了适应各种应用场景，已被刷好的ECU具备广泛适应性，但对于某一款具体的车型来说，可能有些配置功能不适应，会根据车型配置开启或关闭某些软件功能。例如：某些ECU生产厂商来自国际跨国企业，如BOSCH 、SIEMENS 等 ，生产产品销售至全世界。</span>

<span style='background:white'>因每个国家汽油品质、温度、大气压力、湿度、引擎形式上的差异，ECU 程序软件设定上须符合各国的条件，由于现代的汽车要适应各种天气、环境(如高原、沙漠、严寒和劣质汽油等恶劣条件)及各种驾驶者的不同要求，同时它也要保证这种复杂的情况下依然能够挥洒自如行驶并通过严格的尾气排放、油耗标准，因此在大多情形下，</span><span style='font-weight:bold;background:white'>原装ECU内的程序是一个符合众多条件的最佳妥协，这样才不致水土不服，故在设定上保留很多的空间可供配置。</span>

<span style='font-weight:bold;background:white'>所以主机厂会针对不同配置的整车，进行软件功能参数调节或者开启或者关闭某些功能。</span><span style='background:white'>所以在EUC总成之外，还存在一个配置参数的软件类型，该类型主要用于定义不同配置的车型对应的功能参数表。有的企业直接使用EXCEL矩阵表形式表达这个参数配置关系，并将EXCEl作为配置参数（如下图4）的附件对象随BOM一起传递，类似于图纸作为零件的附件对象。也有企业将ECU功能参数进行功能模块化、配置化的管理，并根据整车配置自动生成整车对应的ECU刷写参数文件，软件功能配置化管理参见4.2。</span>

![image6](9f5f83d5f84c4c699b2d24b8f9ee6ab4.png)

<span style='font-style:italic;text-decoration:underline;background:white'>图4 配置参数</span>

<span style='background:white'>对于自主开发的软件，则通常是在生产线边刷写，总成件装配后再刷写软件程序，对于这种模式，则可考虑将软件和ECU总成件并行在产品中管理，如下图5。</span>

![image7](ac4b3d05b83842e8b76a17d368d55f77.jpg)
<span style='font-style:italic;text-decoration:underline;font-family:-apple-system; font-size:10.0pt;color:#888888;background:white'>图5对于自主开发的软件将软件和ECU总成件并行在产品中管理</span>  

<span style='background:white'>供应商只负责提供ECU硬件部分，ECU内的控制程序、标定程序、配置参数则是由主机厂自主研发，并且在生产线边进行刷写。主机厂自主的ECU控制程序，依然存在面向不同配置车型的普适性，针对不同配置的车型仍然需要进行配置参数调整, 软件功能配置化管理参见软件功能配置化管理。</span>

<span style='background:white'>不论是随ECU总成外采的软件还是主机厂自主开发的软件，以上BOM结构管理方式的好处是软硬件的关联关系比较直观，或者可以通过结构层级规则自动计算软硬件的关联关系（如下图6），但是也有弊端，软件变更较为频繁，软件变更会可能影响上级ECU总成件升版或者换号，为避免ECU总成件频繁变号，企业应该制定软硬件升版或换号的控制管理规范。</span>

![image8](443ce833169b4a4eb3821da128e5f138.jpg)
<span style='font-style:italic;text-decoration:underline;font-family:-apple-system; font-size:10.0pt;color:#888888;background:white'>图6 通过结构层级规则自动计算软硬件的关联关系</span>  

### <span style='color:#5B9BD5;text-align:center'> </span>
## <span style='color:#3F3F3F;text-align:center'>2、软件功能配置化管理</span>

<span style='background:white'>软件作为零件，类似于硬件一样，根据软件互换性规则，存在升版或者换号的场景，也跟硬件一样存在于超级BOM下，实现配置化管理，通过车型配置匹配相应的软硬零件。除了这层配置之外，软件功能还存在可配置的场景，同一个软件控制程序在不同配置车型上，所要开启的功能不同，可以对软件进行功能配置化管理（如下图7）。例如车身控制单元，对于同一款车型的高配版车和低配版车，所使用的软件控制程序是一样的，对于高配版来说开启了“无钥匙进入”功能，而低配版则关闭了这一功能。</span>

![image9](046d142320d34826a3082f0fd41fe4fb.png)

<span style='font-style:italic;text-decoration:underline;background:white'>图7 软件的功能配置化管理</span>

<span style='background:white'>两层配置管理：</span>

<span style='color:#346CDD;background:white'>◉ </span><span style='font-weight:bold; background:white'>第一层配置管理：</span><span style='background:white'>软硬件作为车型产品的构成部分，如图7中车身ECU控制组1，作为车型产品的组成模块，纳入超级BOM管理，根据组块的适用配置和具体车型的配置匹配解析到车型应该包含的组块，这是配置化BOM管理的逻辑，此处就不详述。</span>

<span style='color:#346CDD;background:white'>◉</span><span style='font-weight: bold;background:white'>第二层配置管理：</span><span style='background:white'>软件功能配置管理，同一个ECU控制程序有多个功能，如无钥匙进入控制功能、一键升降控制功能等，根据不同车型配置可以设置开启和关闭，或者设置不同功能选项，此时就可以将功能选项与适用配置建立关联，最终可根据车型配置解算出每个具体的车型应该包含开启或关闭什么功能，也即时根据车型配置可解算出配置刷写参数。</span>

### <span style='color:#5B9BD5;text-align:center'> </span>
## <span style='color:#3F3F3F;text-align:center'>3、软件更新管理</span>

<span style='font-family:-apple-system;background:white'>车辆在下线时需要刷写什么软件，通过车型软硬件BOM管理可精确提取，但是软件更新迭代频繁，软件更新后不仅会影响待装配的车辆，也会影响入库车辆或已销售车辆的售后服务，</span><span style='font-weight:bold;font-family:-apple-system;background:white'>软件BOM管理也会对软件更新进行管理，软件更新管理不仅是对软件更新后的登记管理，更多的是软件的变更版本管理，</span><span style='font-family:-apple-system;background:white'>如同零部件变更管理一样，软件的变更也应该纳入企业级BOM的变更管理中，包括版本管理、兼容性管理、版本生效日期、软件版本切换时间、与硬件的配套性、对软件升级变更后受影响车辆分析，对公告车型认证参数的影响分析，保证车型在不同阶段（量产前、量产后、售后）不同时间点能获取到准确、有效的软硬件版本，为生产刷写、售后诊断、OTA升级提供精准的数据支持。</span>  

  

<span style='font-weight:bold;background:whitesmoke'>结 语</span>

<span style='background:white'>当前，越来越多的车企在提倡软硬件分离，软硬件分离主要是针对软件的开发过程，是为了同时推进不同模块的研发，节省研发时间和成本，尽可能降低软件对硬件的依赖性。前文中提到，软件管理包括软件的开发管理、软件BOM管理、软件刷写应用三部分业务。软硬件开发过程分离，但软硬件刷写应用需要组合和关联，</span><span style='font-weight:bold;background:white'>将软件纳入企业统一的BOM管理平台进行管理是连接软硬件分离开发和组合应用的关键桥梁，是汽车产品软硬件数据完整性、一致性、准确性的关键保障。（本文完)</span>
